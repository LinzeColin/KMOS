# DWS 增量媒体归档

只在用户当前线程明确授权采集范围时执行。默认“全量”表示所有可见群、全部历史、图片、照片与视频；每次只处理连续的一个不超过 30 天的历史切片。

先完整读取 `dingtalk-shared` 与 `dingtalk-chat`。只使用官方 `dws` CLI；不读取浏览器 Cookie、钥匙串、钉钉本地数据库或私有接口。

## 固定目的地与目录

- GitHub 根目录：`LinzeColin/Private-Database/Private-KMDatabase/KMVideo/`。
- SMB 根目录：`smb://192.168.0.1/share/03_资料库/MetaData/IDS_MetaData/KMVideo/`；macOS 挂载路径为 `/Volumes/share/03_资料库/MetaData/IDS_MetaData/KMVideo/`。
- GitHub 侧只能通过 `KMDatabase/machine/tools/private_db_client.py` 写入私有库；不 clone `Private-Database`，也不把素材写进 KMOS。
- 不使用 OneDrive。`KMOS/KMVideo/` 仅存源码和路牌，绝不存素材。
- 两个长期目标必须保持同一媒体路径，且媒体目录最多三层：

```text
KMVideo/
  <群名称>/
    photo/<原始照片或图片>
    video/<原始视频>
```

- 不创建 `catalog`、`ledger`、`runs`、按日期分层或其他媒体目录。每个群目录只允许有 `photo/`、`video/` 和一个隐藏的 `.manifest.jsonl` 文件。
- 本机只允许本次运行独有的系统临时目录。不得使用 `KMOS`、`_protected/`、`_scratch/`、OneDrive 或持久目录作为缓存。

## 30 天切片与断点

对每个群维护连续的已完成边界。每次只读取一个相邻、不超过 30 个日历日的消息切片；完成该切片并写入双目的地后，才处理下一个切片。切片不得重叠、跳跃或超过 30 天。

初始切片从用户指定的时间边界开始；后续切片从上一个已完成边界继续，直到 DWS 明确返回该群历史终点。只有全部群都到达各自历史终点，才可报告“所有历史完成”。任何群发生分页、权限或下载错误时，只报告已完成的切片，绝不越过该群断点。

## 增量与双写

每个群的 `.manifest.jsonl` 使用真实 DWS 返回的“群、消息、资源”组合识别素材，并记录 GitHub 与 SMB 两个目的地的完成状态。该文件在两端对应群目录各保留一份相同内容；它是一个文件，不是额外目录。

- 两处都完成：跳过，不重新下载、不重新保存。
- 只有一处完成：只补另一处；已完成的一处绝不覆盖或复制第二份。
- 两处都未完成：从 DWS 下载一次并同时写入两处。
- 原始文件名直接保留在 `photo/` 或 `video/`。若同一群同一目录出现不同素材的同名冲突，在扩展名前追加真实消息 ID；不增加目录层级。

## 单个切片的执行顺序

1. 确认唯一 DWS profile、读取全部可见群，并为每个群确定下一个 30 天切片。
2. 逐页读取该切片内消息；只有 DWS 明确结束分页才算此切片读取完成。
3. 仅提取图片、照片和视频资源，按群名称落入 `photo/` 或 `video/`。
4. 先查该群 `.manifest.jsonl` 的双写状态，跳过已完成素材。
5. 对新增或缺一份副本的素材，在本次运行临时目录中下载一次；写入 GitHub 与 SMB 的对应同一路径。
6. 两处写入都返回成功结果后，在两端更新相同的 `.manifest.jsonl`；若仅一处成功，记录缺失目的地并保留为未完成。
7. 该切片的每条素材都有完成或失败记录后，才推进该群 30 天边界。

## 临时缓存清理

- 每个原始文件在双写完成或失败状态写入后，立即删除本地临时副本。
- 无论成功、部分失败或异常退出，运行收尾都只清理本次运行专属临时目录；不得删除任何其他目录或已有 SMB/GitHub 素材。
- 下次运行先读取 `.manifest.jsonl`，只补未完成的目的地或重新处理失败项；不得把已完成素材当作新素材。

## 报告与视频生成

报告每个切片的群数、时间范围、新增数、GitHub 完成数、SMB 完成数、跳过数、失败数、未完成边界和本机临时目录清理结果。

任何视频生成 Agent 必须先从这两个完全同构的 `KMVideo/<群名称>/photo|video/` 素材库读取全量可用素材，再自行挑选，不要求用户手工筛选。
