## 二、数据从哪到哪

任务引用先申请同源守卫，再按稳定资源引用申请最窄操作锁；全部成功才可进入后续操作，冲突、缺失或陈旧证据一律失败关闭。步骤一只定义契约，不写数据库。

## 三、关键参数为什么这么定

当前值和改哪里在 `06_运维手册.md`，这里只讲**为什么是这个值**。

| 参数 | 为什么定这个值 |
|---|---|
| 租约持续时间 | 必须先取得来源、单位、理由、验证证据与回滚方案，禁止隐式默认值。 |
| 续租间隔 | 必须小于已裁定的租约持续时间，并经独立步骤验证后才能使用。 |
| 过期宽限 | 只能用于处理可证明的时钟与观测误差，不能凭过期时间直接授予所有权。 |
| 获取超时 | 必须在独立步骤中结合资源类型与失败关闭策略定源。 |
| 最大等待 | 不得让锁等待绕过反压、重试预算或人工复核边界。 |
| 重试抖动 | 归属重试策略；锁竞争本身不消耗重试预算，也不创建队列记录。 |
| 死锁超时 | 多锁按规范顺序全有或全无获取；任何超时值仍须独立定源与验证。 |
