# KM_IDSystem Agent 规则

默认用户可见输出使用中文。

## S4 精简执行胶囊

普通任务先读本文件、`README.md` 和被任务直接点名的任务/证据文件；不得扫描无关项目。

- 不得读取完整 `模型参数文件.md`，除非变更涉及路由、优化规则、安全策略、评分、阈值、
  模型参数或发布验收。
- 治理验证：`python -B scripts/lean_governance.py validate --project KM_IDSystem --semantic`。
- owner 预览：`python -B scripts/lean_governance.py check-render --project KM_IDSystem`。
- 应用变更先补任务点名的窄后端/前端测试，再考虑 broad test discovery。

## 边界

- 不得编造 owner 决策或生产就绪结论。
- 数据、缓存、本地运行输出和 secrets 不得进入 Git，除非当前任务明确允许提交脱敏证据。

- **结论**：整阶段复审必须同时失败关闭 P1--P4 合同、控制报告、状态形状与零运行时边界。
  **为什么**：单独的 P4 交付通过不能证明 P1--P3 未漂移；Review 必须保留 P4→P3 回退，并把后继严格停在下一阶段 P1 门禁。
  **代价**：没量。

- **结论**：Stage074 P1 的本地 Embedding 兜底只能以未选模型、未执行的静态合同交付。
  **为什么**：在业务线白箱人工复核、单一权威和零 Token 生产边界下，模型选择、下载、Embedding、索引、队列或审计写入都属于后续受控门，不能被 P1 提前宣称或执行。
  **代价**：没量。

- **结论**：Stage074 P2 只可用固定、非业务、`reference-only` 控制标签在内存中投影策略继承、队列/缓存/重试、成本、模型版本和审计形状，并让历史白箱测试显式保留 P1 与接受 P2 后继状态。
  **为什么**：把控制投影误作真实 provider、模型、文本块或持久记录会突破单一权威与零运行时边界；只更新当前 P2 而不保留历史合法状态会让既有治理回归把正常阶段推进误报为失败。
  **代价**：没量。

- **结论**：Stage074 P3 必须只重放 P2 的固定 reference-only 控制投影，并同时把历史测试、批次检查器与 Stage005 的“当前态”和“历史批次兼容态”拆开扩展到 P3/P4-gate。
  **为什么**：P3 场景不能产生真实外发、模型或持久运行时；而把历史 batch 条件混入 current-roadmap 条件会让主检查器表面通过、历史回归却全部 fail-closed。P3 只应增加合法后继，不改写 P1/P2 或旧批次事实。
  **代价**：一次完整 Stage005 回归约 92 秒；未拆开条件时 28 个旧阶段用例同时失败。

- **结论**：Stage074 P4 必须只从 P3/P2 固定 `:control:` 投影派生 metadata-only 交付，并让 P4→P3 回退不触及真实状态；历史测试、批次检查器与 Stage005 必须显式兼容 P4-current 和历史批次态。
  **为什么**：P4 的样例、审计投影、零值成本、失败处理和查询指引不是业务事实或真实外发记录；遗漏 P1 合同证据引用会使 Stage005 无法解析 P4 当前节点，即使其他字段正确。
  **代价**：一次 Stage005 全量单元回归约 98 秒；本轮因一处证据引用遗漏返工一次。

- **结论**：Stage074 Review 必须把“P1--P4 均通过”的结论绑定到每个冻结形状、P4→P3 回退、单一权威和全套零运行时标志，并把所有历史后继断言精确延长到 `Review → Stage075 P1 gate`。
  **为什么**：只更新当前 Review 文档会让旧白箱测试把合法推进误报为失败；反过来，宽松替换会破坏非状态断言。历史用例若篡改的字段已不再驱动当前态，应保留其历史证据断言，并改验真实当前 Review 路由仍失败关闭。先按失败组修复精确后继表、再跑合并回归，才能既保留历史事实又验证当前态。
  **代价**：本轮 473 项 Stage060--069 回归从 49 个旧后继断言失败收敛到全绿；Stage005 全量回归还暴露 20 个旧当前态假设，改为当前路由失败关闭后 178/178 通过；一次过宽多行替换被语法检查提前捕获并精确修复。

- **结论**：Stage075 P1 的历史批次兼容必须以当前 roadmap 的精确 P1 节点为唯一事实，并只把既有批次作为兼容证据。
  **为什么**：向旧 batch YAML 写入 Stage075 当前节点会制造第二权威；而只扩展当前节点又会让历史回归失去合法后继。Stage005 的篡改测试必须修改实际 current_phase，才能验证当前路线仍失败关闭。
  **代价**：本轮完整 Stage005 治理回归约 121 秒；未区分当前节点与历史批次兼容时，需要一次定向修复后才恢复全绿。

- **结论**：Stage075 P2 必须把 `chunk_id` 保持为 `chunk_ref` 的不透明控制别名，并把 owner 强制允许外发限制为独立的四字段前置投影。
  **为什么**：控制切片需要能验证策略继承、未授权阻断与审计字段形状，但不能把固定引用误写成真实 chunk、外发或持久审计记录；历史白箱只应新增精确的 `P2 → P3 gate` 后继。
  **代价**：没量。

- **结论**：Stage075 P3 应仅重放 P2 的五条固定控制投影，并把所有历史白箱中允许的当前态精确延长为 `P3 → P4 gate`，同时保留 P1/P2 的历史断言。
  **为什么**：只新增 P3 模块而遗漏早期阶段的允许集合，会让当前治理事实已推进、历史回归仍把它误判为非法；将 P3 误作真实外发、摘要/文本载荷或持久审计又会突破单一权威与零运行时边界。

- **结论**：Stage075 P4 只能由 P3/P2 的固定、非业务控制投影派生交付证据；历史合法后继必须逐个元组延长为 `P4 → Review gate`，不可作全局字符串替换。
  **为什么**：策略样例、十九字段审计投影、零值成本、失败处理、未外发原因、查询说明和 owner 四字段前置都不是业务事实、真实外发或持久审计；过宽替换会把无 gate 的历史元组变成非法四元组，既掩盖旧事实又破坏回归。
  **代价**：本轮先由精确后继补齐把 Stage060--069 的历史回归恢复为 `473/473`；两种无 gate 元组须单独回正，才能保留 P1--P3 历史状态并验证 P4 的唯一后继。

- **结论**：推进到新的 P1 后，历史白箱既要精确追加完整的当前 `(stage, phase, task, next_gate)`，也要在生成的 `05_执行与验收.md` 中允许新的当前验收 ID 与本地 run ID 成对出现。
  **为什么**：状态白名单即使已接受新 P1，渲染前的回归也可能因旧中文视图仍包含历史 run 而通过；最终渲染后，早期用例会因只认可旧验收／回执对而失败。两类后继断言都必须保持精确，不能放宽成任意 Stage080 文本。
  **代价**：Stage080 P1 最终渲染后暴露 3 个早期历史断言缺口；补齐后 Stage060--080 `933/933`，未产生运行时动作。
