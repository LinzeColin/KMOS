- 本地编号：D16-S005
- 当前版本：v0.1
- 能力域：D16 · RAG 回答层与安全
- 入口：IDS 系统运营入口
- Acceptance ID：ACC-STAGE-101
- 建议并行度：否
- 并行说明：本 Stage 涉及共享契约、状态机、数据库、索引、证据、报告或执行规则，建议单独完成后再进入下游。
- 预计实际执行开发时间：12-24 小时

## 追求目标（Pursuing Goal）

让每次 RAG 回答像量化回测一样可复现。

## Codex 执行范围

### 允许

- 只处理本 Stage 明确相关文件。
- 可以新增本 Stage 所需的代码、schema、测试、配置、文档或 UI 切片。
- 必须输出修改文件列表、真实测试结果、验收证据和回滚说明。

### 禁止

- 不得提交真实原始资料。
- 不得提交 secrets、API key、数据库密码或云端凭证。
- 不得移动、删除、覆盖 `00_ORIGINAL_RAW_DATA`。
- 不得把旧产品名用于新 UI、报告、文档显示名。
- 不得声称测试通过但没有真实测试输出。
- 不得扩大到其他 Stage 的范围。

## Phase / Task

### Phase 1：范围、输入输出与边界确认
1. 定义 RAG 回答结构、prompt 版本、内部依据、外部增强、无内部依据策略和模型输出权限。
2. 确认检索文档永远只是 evidence，不是系统指令。
3. 定义模型输出分类和人工确认门禁。

### Phase 2：实现、接入与最小可运行切片
1. 实现回答合同、prompt version、source_type 分离、提示注入防护或输出权限门禁。
2. 记录 query、index_version、prompt_version、model_version、selected evidence。
3. 将外部公开参考和模型推理合并为外部增强意见显示，但底层保留来源类型。

### Phase 3：RAG 可复现 专项验证与异常场景
1. 验证文档内提示词无法覆盖 IDS 规则。
2. 验证无内部证据时不会伪装成内部经验。
3. 验证高风险工程建议、合同承诺、生产写回不会自动进入最终结论。

### Phase 4：RAG 可复现 交付证据、回滚与中文反馈
1. 交付 RAG 回答样例、负向测试结果、prompt/version 记录和可复现日志。
2. 记录模型输出权限边界。
3. 提供 prompt 回滚和模型配置回退说明。

## 验收标准

- 追求目标对应能力已经可运行，或已形成可执行、可测试、可回滚的工程合同。
- 本 Stage 的失败状态、停止条件、审计记录、回滚路径明确。
- 本 Stage 不破坏原始资料、manifest、证据账本、审计日志和已交付报告。
- 相关测试、场景验证或文档证据真实存在。
- 中文交互反馈清楚、克制、面向企业用户，不使用夸大或 AI 化承诺。

## 停止条件

- 需要真实资料但没有 fixture 或 owner 授权样本。
- 可能删除、移动、覆盖原始文件。
- schema migration 无法回滚。
- 测试失败且原因不明。
- 修改范围超出本 Stage。
- 并行开发导致共享文件冲突。

## 回滚方式

回滚本 Stage 的代码、schema、配置或 UI 变更；不得影响原始资料、manifest、evidence ledger、audit log 和已交付报告。若本 Stage 产生派生产物，应只清理明确允许清理的临时文件或可重建缓存。
