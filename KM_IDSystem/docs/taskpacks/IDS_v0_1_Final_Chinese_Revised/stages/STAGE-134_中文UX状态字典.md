## 追求目标（Pursuing Goal）

统一中文状态文案，避免 AI 味、旧名称、过度承诺和技术黑话。

## Codex 执行范围

### 允许

- 只处理本 Stage 明确相关文件。
- 可以新增本 Stage 所需的代码、schema、测试、配置、文档或 UI 切片。
- 必须输出修改文件列表、真实测试结果、验收证据和回滚说明。

### 禁止

- 不得提交真实原始资料。
- 不得提交 secrets、API key、数据库密码或云端凭证。
- 不得移动、删除、覆盖 `00_ORIGINAL_RAW_DATA`。
- 不得把旧产品名用于新 UI、报告、文档显示名。
- 不得声称测试通过但没有真实测试输出。
- 不得扩大到其他 Stage 的范围。

## Phase / Task

### Phase 1：范围、输入输出与边界确认
1. 定义人类产品入口的信息架构、状态词典、页面跳转和客户信任反馈。
2. 确认客户页面只显示人类需要理解和操作的内容。
3. 定义机器状态到人类状态的压缩映射。

### Phase 2：实现、接入与最小可运行切片
1. 实现导航、数据源中心、资料台账、知识检索、报告中心或信任看板切片。
2. 把复杂机器状态转译为中文业务状态。
3. 提供加载、成功、失败、重试、禁用和危险确认反馈。

### Phase 3：中文 UX 状态字典 专项验证与异常场景
1. 走查资料接入、预检、处理进度、检索、证据、报告、复核等完整流程。
2. 验证页面不暴露 worker、queue、数据库参数等机器细节。
3. 验证中文文案不 AI 化、不夸大、不使用旧产品名。

### Phase 4：中文 UX 状态字典 交付证据、回滚与中文反馈
1. 交付页面流转说明、状态字典、截图占位或交互验收清单。
2. 记录用户困惑点和下一步建议面板规则。
3. 提供 UI 回滚和功能开关说明。
