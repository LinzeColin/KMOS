# STAGE-150 · 危险操作确认

- 本地编号：D24-S003
- 当前版本：v0.1
- 能力域：D24 · 安全与审计
- 入口：IDS 系统运营入口
- Acceptance ID：ACC-STAGE-150
- 建议并行度：否
- 并行说明：本 Stage 涉及共享契约、状态机、数据库、索引、证据、报告或执行规则，建议单独完成后再进入下游。
- 预计实际执行开发时间：4-12 小时

## 追求目标（Pursuing Goal）

移动、删除、覆盖、外发、清空队列、切换索引等危险操作必须确认。

## Codex 执行范围

### 允许

- 只处理本 Stage 明确相关文件。
- 可以新增本 Stage 所需的代码、schema、测试、配置、文档或 UI 切片。
- 必须输出修改文件列表、真实测试结果、验收证据和回滚说明。

### 禁止

- 不得提交真实原始资料。
- 不得提交 secrets、API key、数据库密码或云端凭证。
- 不得移动、删除、覆盖 `00_ORIGINAL_RAW_DATA`。
- 不得把旧产品名用于新 UI、报告、文档显示名。
- 不得声称测试通过但没有真实测试输出。
- 不得扩大到其他 Stage 的范围。

## Phase / Task

### Phase 1：范围、输入输出与边界确认
1. 定义审计事件、外部 API 审计、危险操作确认和 secrets 处理基线。
2. 确认 secrets、API key、数据库密码不得进入 Git。
3. 定义 audit event 的 actor、time、object、action、result 字段。

### Phase 2：实现、接入与最小可运行切片
1. 实现审计 schema、外部 API 审计、危险操作确认或 secret 检查切片。
2. 所有外发、导出、配置变更、危险操作必须可追踪。
3. 把安全失败转为可理解状态而非静默失败。

### Phase 3：危险操作确认 专项验证与异常场景
1. 验证禁止外发、路径穿越阻断、危险操作确认、secret 不入库不入 Git。
2. 验证审计日志不可被普通操作清理。
3. 验证安全失败有明确中文提示。

### Phase 4：危险操作确认 交付证据、回滚与中文反馈
1. 交付审计样例、安全测试结果和危险操作清单。
2. 记录仍未启用的企业级权限能力。
3. 提供安全配置回滚和密钥轮换说明。

## 验收标准

- 追求目标对应能力已经可运行，或已形成可执行、可测试、可回滚的工程合同。
- 本 Stage 的失败状态、停止条件、审计记录、回滚路径明确。
- 本 Stage 不破坏原始资料、manifest、证据账本、审计日志和已交付报告。
- 相关测试、场景验证或文档证据真实存在。
- 中文交互反馈清楚、克制、面向企业用户，不使用夸大或 AI 化承诺。

## 停止条件

- 需要真实资料但没有 fixture 或 owner 授权样本。
- 可能删除、移动、覆盖原始文件。
- schema migration 无法回滚。
- 测试失败且原因不明。
- 修改范围超出本 Stage。
- 并行开发导致共享文件冲突。

## 回滚方式

回滚本 Stage 的代码、schema、配置或 UI 变更；不得影响原始资料、manifest、evidence ledger、audit log 和已交付报告。若本 Stage 产生派生产物，应只清理明确允许清理的临时文件或可重建缓存。
