## 追求目标（Pursuing Goal）

定义临时文件、缓存、旧索引、日志、报告快照的保留策略字段。

## Codex 执行范围

### 允许

- 只处理本 Stage 明确相关文件。
- 可以新增本 Stage 所需的代码、schema、测试、配置、文档或 UI 切片。
- 必须输出修改文件列表、真实测试结果、验收证据和回滚说明。

### 禁止

- 不得提交真实原始资料。
- 不得提交 secrets、API key、数据库密码或云端凭证。
- 不得移动、删除、覆盖 `00_ORIGINAL_RAW_DATA`。
- 不得把旧产品名用于新 UI、报告、文档显示名。
- 不得声称测试通过但没有真实测试输出。
- 不得扩大到其他 Stage 的范围。

## Phase / Task

### Phase 1：范围、输入输出与边界确认
1. 定义 PostgreSQL 控制面的 schema、迁移、连接、存储边界和恢复要求。
2. 确认 PostgreSQL 存控制面、状态和热索引，不存 500GB 原始文件。
3. 定义 migration 必须可回滚、可验证。

### Phase 2：实现、接入与最小可运行切片
1. 实现 schema、迁移脚本、连接配置、约束或恢复冒烟测试。
2. 为数据库大小、连接池和质量约束设置护栏。
3. 把 schema 变更记录到治理文件和机器可读索引。

### Phase 3：数据保留表 专项验证与异常场景
1. 验证 migration dry-run、重复执行、失败回滚和恢复冒烟。
2. 验证数据库不会写入原始大文件或无限制派生产物。
3. 验证连接池、事务边界和约束错误可解释。

### Phase 4：数据保留表 交付证据、回滚与中文反馈
1. 交付 schema diff、migration 输出、恢复测试日志和已知限制。
2. 记录需要人工确认的破坏性迁移。
3. 写明数据库回滚和备份恢复步骤。

## 验收标准

- 追求目标对应能力已经可运行，或已形成可执行、可测试、可回滚的工程合同。
- 本 Stage 的失败状态、停止条件、审计记录、回滚路径明确。
- 本 Stage 不破坏原始资料、manifest、证据账本、审计日志和已交付报告。
- 相关测试、场景验证或文档证据真实存在。
- 中文交互反馈清楚、克制、面向企业用户，不使用夸大或 AI 化承诺。

## 停止条件

- 需要真实资料但没有 fixture 或 owner 授权样本。
- 可能删除、移动、覆盖原始文件。
- schema migration 无法回滚。
- 测试失败且原因不明。
- 修改范围超出本 Stage。
- 并行开发导致共享文件冲突。

## 回滚方式

回滚本 Stage 的代码、schema、配置或 UI 变更；不得影响原始资料、manifest、evidence ledger、audit log 和已交付报告。若本 Stage 产生派生产物，应只清理明确允许清理的临时文件或可重建缓存。
