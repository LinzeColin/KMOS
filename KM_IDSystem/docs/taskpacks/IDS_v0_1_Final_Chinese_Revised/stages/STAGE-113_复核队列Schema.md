## 追求目标（Pursuing Goal）

建立人工复核队列，接收低 OCR 置信度、资料冲突、证据风险、解析失败等项目。

## Codex 执行范围

### 允许

- 只处理本 Stage 明确相关文件。
- 可以新增本 Stage 所需的代码、schema、测试、配置、文档或 UI 切片。
- 必须输出修改文件列表、真实测试结果、验收证据和回滚说明。

### 禁止

- 不得提交真实原始资料。
- 不得提交 secrets、API key、数据库密码或云端凭证。
- 不得移动、删除、覆盖 `00_ORIGINAL_RAW_DATA`。
- 不得把旧产品名用于新 UI、报告、文档显示名。
- 不得声称测试通过但没有真实测试输出。
- 不得扩大到其他 Stage 的范围。

## Phase / Task

### Phase 1：范围、输入输出与边界确认
1. 定义人工复核队列、状态、审计和复核结果对证据等级的影响。
2. 确认低 OCR、资料冲突、解析失败、证据风险必须能进入复核。
3. 定义待复核、已确认、已拒绝、需补资料、已归档状态。

### Phase 2：实现、接入与最小可运行切片
1. 实现复核 schema、复核工作流、复核 UI、复核审计或冲突队列切片。
2. 把复核结果写回证据风险和报告状态。
3. 提供人类可理解的复核原因。

### Phase 3：复核队列 Schema 专项验证与异常场景
1. 验证低质量 OCR、冲突资料、撤回资料、外部增强替代内部证据等场景。
2. 验证复核操作有 actor、time、reason、old/new value。
3. 验证复核结果影响 evidence trust level 和报告质量分。

### Phase 4：复核队列 Schema 交付证据、回滚与中文反馈
1. 交付复核队列样例、复核审计日志和 UI 流程截图或说明。
2. 记录需人工判断的边界。
3. 提供复核回滚和重新复核说明。
