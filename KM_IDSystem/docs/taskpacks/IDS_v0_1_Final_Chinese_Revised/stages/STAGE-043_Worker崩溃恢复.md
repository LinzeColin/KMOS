## 追求目标（Pursuing Goal）

验证 worker 崩溃后任务状态不丢失，并能继续或安全失败。

## Codex 执行范围

### 允许

- 只处理本 Stage 明确相关文件。
- 可以新增本 Stage 所需的代码、schema、测试、配置、文档或 UI 切片。
- 必须输出修改文件列表、真实测试结果、验收证据和回滚说明。

### 禁止

- 不得提交真实原始资料。
- 不得提交 secrets、API key、数据库密码或云端凭证。
- 不得移动、删除、覆盖 `00_ORIGINAL_RAW_DATA`。
- 不得把旧产品名用于新 UI、报告、文档显示名。
- 不得声称测试通过但没有真实测试输出。
- 不得扩大到其他 Stage 的范围。

## Phase / Task

### Phase 1：范围、输入输出与边界确认
1. 定义 job 状态机、worker 边界、重试、死信、反压、锁和自动生命周期。
2. 确认移动硬盘离线、磁盘不足、预算不足时应暂停相关任务。
3. 定义幂等键、锁粒度和半成品输出清理规则。

### Phase 2：实现、接入与最小可运行切片
1. 实现最小任务队列、状态转换、失败重试、反压或自动运行切片。
2. 把机器端状态映射为人类可理解状态。
3. 记录每个任务的输入、输出、错误和 checkpoint。

### Phase 3：Worker 崩溃恢复 专项验证与异常场景
1. 验证重复点击、worker 崩溃、移动硬盘拔掉、低磁盘、并发处理同一文件等场景。
2. 验证锁能阻止重复处理、重复解压、重复索引和重复报告。
3. 验证后台清理不会删除事实源、证据账本、报告快照和审计日志。

### Phase 4：Worker 崩溃恢复 交付证据、回滚与中文反馈
1. 交付 job 状态图、失败重试日志、反压触发证明和清理白名单。
2. 记录可以自动恢复和必须人工处理的情况。
3. 提供安全关闭、恢复和回滚说明。
