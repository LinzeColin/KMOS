## 追求目标（Pursuing Goal）

资料撤回、降级或冲突时同步更新 evidence 状态。

## Codex 执行范围

### 允许

- 只处理本 Stage 明确相关文件。
- 可以新增本 Stage 所需的代码、schema、测试、配置、文档或 UI 切片。
- 必须输出修改文件列表、真实测试结果、验收证据和回滚说明。

### 禁止

- 不得提交真实原始资料。
- 不得提交 secrets、API key、数据库密码或云端凭证。
- 不得移动、删除、覆盖 `00_ORIGINAL_RAW_DATA`。
- 不得把旧产品名用于新 UI、报告、文档显示名。
- 不得声称测试通过但没有真实测试输出。
- 不得扩大到其他 Stage 的范围。

## Phase / Task

### Phase 1：范围、输入输出与边界确认
1. 定义 Evidence Ledger、证据缺口、风险评分、可信等级、撤回和知识库投毒防护。
2. 确认每条关键结论必须关联 evidence_id 或 evidence_gap。
3. 定义 A/B/C/D/E 证据等级。

### Phase 2：实现、接入与最小可运行切片
1. 实现证据 schema、检索证据捕获、风险评分、撤回或投毒防护切片。
2. 把 evidence 与 document、chunk、fact、query、answer、report 关联。
3. 将低可信、冲突、过期和撤回证据降级。

### Phase 3：证据撤回 专项验证与异常场景
1. 验证无内部证据、低 OCR、旧版本、冲突资料、撤回资料和恶意资料场景。
2. 验证撤回证据会影响报告状态。
3. 验证高可信结论不能使用低等级证据伪装。

### Phase 4：证据撤回 交付证据、回滚与中文反馈
1. 交付 evidence ledger 样例、证据等级报告、撤回影响清单和回归测试。
2. 记录不可作为结论依据的证据类型。
3. 提供证据降级、撤回和恢复说明。
