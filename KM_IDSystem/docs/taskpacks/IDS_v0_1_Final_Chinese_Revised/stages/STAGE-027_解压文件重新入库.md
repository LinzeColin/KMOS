## 追求目标（Pursuing Goal）

解压后的文件重新进入 hash、manifest、dedup、parser pipeline。

## Codex 执行范围

### 允许

- 只处理本 Stage 明确相关文件。
- 可以新增本 Stage 所需的代码、schema、测试、配置、文档或 UI 切片。
- 必须输出修改文件列表、真实测试结果、验收证据和回滚说明。

### 禁止

- 不得提交真实原始资料。
- 不得提交 secrets、API key、数据库密码或云端凭证。
- 不得移动、删除、覆盖 `00_ORIGINAL_RAW_DATA`。
- 不得把旧产品名用于新 UI、报告、文档显示名。
- 不得声称测试通过但没有真实测试输出。
- 不得扩大到其他 Stage 的范围。

## Phase / Task

### Phase 1：范围、输入输出与边界确认
1. 定义压缩包安全边界、解压 staging 区、文件数量限制、体积限制和嵌套限制。
2. 确认自动解压不覆盖原始压缩包，不写出指定目录。
3. 定义 archive_manifest 和解压后重新入库规则。

### Phase 2：实现、接入与最小可运行切片
1. 实现安全解压、路径过滤、风险标记和解压产物重新进入导入管线。
2. 把解压失败、风险文件、超限文件写入人工复核或隔离状态。
3. 建立清理白名单，不清理事实源和证据产物。

### Phase 3：解压文件重新入库 专项验证与异常场景
1. 用路径穿越、绝对路径、压缩炸弹、嵌套包、乱码文件名和超大文件数样例验证防护。
2. 验证解压后文件重新进入 hash、manifest、dedup、parser 流程。
3. 验证自动清理只清理允许的临时文件，不删除原始文件。

### Phase 4：解压文件重新入库 交付证据、回滚与中文反馈
1. 交付 archive_manifest 样例、安全阻断日志和清理白名单。
2. 记录自动解压风险边界和停止条件。
3. 提供 staging 区回滚和清理说明。
