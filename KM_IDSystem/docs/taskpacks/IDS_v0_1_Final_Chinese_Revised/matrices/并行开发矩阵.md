# 并行开发矩阵与规则

## 总原则

- “建议并行度：否”的 Stage 不要并行开发。
- “建议并行度：是”的 Stage 也必须限定文件范围、Acceptance ID 和集成验证。
- 同一个 worktree 可以开多个 Codex thread，但不要让多个 thread 同时修改同一批共享文件。

## 可以较早并行推进的任务

1. STAGE-006 至 STAGE-011：本地环境和存储根目录，可与 STAGE-001 至 STAGE-005 的仓库治理并行。
2. STAGE-018 至 STAGE-023：导入预检，可与 STAGE-024 的压缩包威胁模型、STAGE-152 的黄金测试集准备并行。
3. STAGE-051 至 STAGE-056：OCR 回归样例和管线设计，可与 STAGE-057 至 STAGE-062 的表格样例准备并行。
4. STAGE-119 至 STAGE-123：数据质量门禁，可与对应能力域实现并行设计，但最终必须在 STAGE-168 前通过。
5. STAGE-127 至 STAGE-135：人类产品入口 UI，可在后端接口合同稳定后并行推进。
6. STAGE-143 至 STAGE-147：备份恢复，可与数据库控制面阶段并行设计；rclone/云端备份方案可在单独线程同步推进。
7. STAGE-152 至 STAGE-161：测试、压测、UI/UX 走查和交叉验证，可作为横切质量工作并行推进。

## 不建议并行的任务

1. STAGE-030 至 STAGE-036：PostgreSQL 控制面和迁移。
2. STAGE-037 至 STAGE-044：任务状态机、worker 队列、锁、反压和自动生命周期。
3. STAGE-076 至 STAGE-082：索引版本、原子切换和回滚。
4. STAGE-089 至 STAGE-096：证据账本、证据等级、撤回和知识库投毒防护。
5. STAGE-097 至 STAGE-104：RAG 安全、prompt 版本和模型输出权限。
6. STAGE-162 至 STAGE-168：Codex 执行治理、并行策略、发布包和 v0.1 最终验收。

## 并行 thread 的最低要求

每个 Codex thread 必须写明：

```text
Stage ID
Acceptance ID
Pursuing Goal
Allowed files
Forbidden files
预计修改范围
预计测试命令
停止条件
```

如果无法明确文件范围，不要并行。
