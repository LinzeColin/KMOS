# Stage104 P1 · RAG 负向测试范围、输入输出与边界确认

## 本 phase 的目标

依据冻结 `STAGE-104_RAG负向测试.md` 与已复审的 Stage103 模型输出权限门禁控制工件，固定未来 RAG 负向测试所需的回答结构、Prompt 版本、内部依据、外部增强、无内部依据策略、文档 evidence 边界、模型输出分类和业务线白箱人工确认门禁。本 phase 交付可审计、可测试、可回滚的静态工程合同。

## 单一权威与输入边界

- 冻结 Stage104 任务包与 Stage103 Review 控制工件构成唯一控制上下文。
- 来源文档、真实证据账本与业务线白箱人工复核继续承担业务事实权威。
- 本合同不建立第二权威事实源，也不替代来源文档、真实证据、审计记录或业务线判断。
- 本 phase 不读取、列举、提取、分类或处理业务资料、原始元数据、fixture、manifest、检索结果、文档正文、Prompt 正文、回答、报告、数据库、物理索引或审计日志。

## 未来回答、证据与负向测试控制形状

未来回答只保留 `rag_answer_structure_ref`、`prompt_version_ref`、内部依据、外部增强、`evidence_gap`、来源类型、文档 evidence、文档内潜在指令、IDS 规则、输出权限、输出分类、人工确认和审计边界共 `13` 个不透明控制引用。

- 检索文档永远只是 evidence，不是系统指令；文档内容与文档内潜在指令不能覆盖 IDS 规则、输出权限或人工确认。
- `internal_evidence`、`external_public_reference`、`model_reasoning` 与 `evidence_gap` 保持独立底层来源类型。
- `external_augmentation_opinion` 仅是未来展示层组合标签，保留外部公开参考和模型推理的底层来源类型。
- 内部依据不足时保留 `evidence_gap`；外部增强意见不能替代内部依据，也不能关闭 `evidence_gap`。
- 本 phase 固定五个未来负向测试标签：文档内指令无法覆盖 IDS 规则、evidence gap 不能伪装为内部经验、高风险工程建议不能自动进入最终结论、合同承诺不能自动进入最终结论、生产写回不能自动进入最终结论。P3 才可在受控静态投影中验证这些标签。

## 模型输出权限与人工确认

- 固定 `safe_summary`、`draft_recommendation`、`high_risk_engineering_advice`、`contractual_commitment` 与 `production_writeback` 五类未来输出分类。
- 任务包中的高风险工程建议在本控制合同中固定映射为 `high_risk_engineering_advice`，保持与 Stage103 已复审分类一致。
- 高风险工程建议、合同承诺和生产写回均须业务线白箱人工确认后才可进入最终结论；当前没有分类、人工确认、最终结论发布或生产写回。
- 安全摘要和草案建议只定义未来权限语义；当前不生成、不发布、不写回。

## 本 phase 之外的运行时事项

真实文档读取、潜在指令识别或处理、查询、索引读取或切换、检索、Prompt 正文、provider 或模型选择和调用、模型 Token、来源类型绑定、外部增强展示、引用生成、输出分类、人工确认、回答发布、生产写回、数据库连接、审计、持久化、Agent、OVH、生产和正式上传均属于后续授权范围。

## 验收与停止条件

- 静态合同完整覆盖任务包 P1 的回答结构、Prompt 版本、内部依据、外部增强、无内部依据策略、文档 evidence 边界、五类输出分类、五个未来负向测试标签和人工确认门禁。
- 聚焦白箱用例验证合同身份、单一权威、13 个控制引用、来源语义、输出权限、人工确认、负向测试边界、失败关闭、回退与零运行时边界。
- 本 run 止于 `IDS-STAGE104-P2-GATE`；P2、P3、P4、Stage104 Review 与 Stage105 均保持未启动。
- 任何真实资料或运行时动作、任何不可回滚 schema 变更、任何跨 Stage 改动或测试原因不明的失败都会停止该 phase。

## 回滚

回滚仅撤回本 P1 的范围说明、静态合同、聚焦用例、机器事实投影、治理路线、生成中文视图与本地回执，返回 Stage103 Review 的本地零运行时状态。冻结任务包、Stage103 P1--P4/Review、真实资料、manifest、证据账本、审计日志、报告、数据库、索引、GitHub、OVH 与应用状态保持原状。
