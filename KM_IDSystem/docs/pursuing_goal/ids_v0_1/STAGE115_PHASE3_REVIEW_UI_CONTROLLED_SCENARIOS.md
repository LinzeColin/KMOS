# Stage115 P3 · 复核 UI 专项异常场景与白箱门禁

## 本 run 的目标

本阶段机械重放 Stage115 P2 的五条固定、非业务、`reference-only` 复核 UI 控制请求，形成五条可验证的专项场景控制记录：

1. 低质量 OCR 的复核操作控制；
2. 冲突资料的复核审计控制；
3. 撤回资料的重新复核控制；
4. 复核结果对 evidence trust level 与报告质量分的未来影响控制；
5. 外部增强替代内部证据的来源分离控制。

每条场景固定 `47` 个字段，五条共 `235` 个场景检查点；同时形成五个控制视图和五条业务线白箱处理记录。P2 前序控制形状保持为五条请求、每条 `23` 个输入字段、十九个 P1 控制引用、四组投影、每条 `117` 个字段、合计 `585` 个前序检查点。

## 控制语义

- 每条复核操作保留 actor、time、reason、old value、new value、review result、review audit、重新复核与归档的未来控制引用。
- evidence trust level 与报告质量分保留 before/after、报告状态影响和未来写回控制引用；本阶段只形成控制记录。
- 撤回资料场景承接 P2 的 parsing failure / needs more material 控制形状，固定重新复核与归档引用，不读取或标记真实资料。
- 外部增强保持外部来源身份；内部证据绑定、证据缺口和最终业务结论继续由业务线白箱人工确认承接。
- 五条业务线白箱处理记录均要求后续人工确认；本阶段保持零人工确认和零最终业务结论记录。

## 输入、输出与单一权威

冻结 Stage115 任务包、Stage115 P1/P2 控制工件和 Stage114 Review 工件构成工程控制上下文。来源文档、真实证据账本、已交付报告、既有审计日志与业务线白箱人工复核继续承担业务事实权威。本阶段不建立第二权威事实源。

输出包括本范围说明、纯内存模块、合同、聚焦白箱用例、机器事实、治理投影、中文视图和本地 receipt。它们均为工程控制证据，不是复核队列、审计日志、证据账本、报告或业务结论。

## 零运行时边界

真实资料、OCR、冲突、撤回、解析、证据风险、复核队列、UI、审计、数据库、证据可信等级、报告质量分、报告状态、人工确认、模型、模型 Token、Agent、OVH、生产、正式全局上传和 push 保持零执行。控制输入漂移、P2 形状漂移、审计字段缺失、影响控制缺失、外部增强边界失配或自动执行标志出现时，模块返回失败关闭结果，场景、控制视图和白箱处理记录保持为空。

## 停止与回滚

本 run 止于 `IDS-STAGE115-P4-GATE`。P4 才交付复核队列样例、复核审计日志和 UI 流程说明，整阶段 Review 保持后续门禁。

回滚只撤回本 P3 的范围说明、纯内存场景模块、合同、聚焦用例、machine run、机器事实、治理路线、事件、生成中文视图、变更记录和交接，恢复到 `PASS_IN_MEMORY_REVIEW_UI_CONTROL_SLICE_RUNTIME_DISABLED`。Stage115 P1/P2、Stage114 Review、冻结任务包、来源文档、真实证据账本、已交付报告、既有审计日志、数据库、GitHub、OVH 与应用状态保持既有边界。
