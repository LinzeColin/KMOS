# Stage102 P3 · 文档内提示注入防护专项验证与异常场景

## 本 phase 的目标

依据冻结 `STAGE-102_文档内提示注入防护.md`、Stage102 P1 静态合同、Stage102 P2 纯内存控制切片和 Stage101 Review 工件，机械重放固定控制投影，验证文档内潜在指令不能覆盖 IDS 规则、内部依据不足保持 `evidence_gap`、三类高风险输出保持业务线白箱人工确认与最终结论未发布。

## 单一权威与输入边界

- 冻结 Stage102 任务包、Stage102 P1/P2 和 Stage101 Review 控制工件构成唯一控制上下文。
- 来源文档、真实证据账本与业务线白箱人工复核继续承担业务事实权威；本场景报告不能替代来源文档或形成业务事实。
- 输入只来自 Stage102 P2 的七条固定、非业务、`reference-only` 控制请求及其投影。控制引用不包含业务事实、来源正文或路径、真实文档指令、查询、Prompt、模型配置、evidence、引用、回答或业务结论。
- 本 phase 不读取、列举、提取、分类或处理业务资料、原始元数据、fixture、manifest、检索结果、文档正文、Prompt 正文、回答、报告、数据库、物理索引或审计日志。

## 受控场景形状

- 严格重放 P2 的 `7` 条、每条 `28` 字段、四组投影、每条 `50` 字段、共 `350` 个前序控制检查点。
- 固定 `7` 条场景结果，每条 `34` 字段、共 `238` 个场景检查点，覆盖 IDS 规则优先、evidence_gap 语义、工具或外部动作拒绝、Prompt 或模型配置拒绝、合同承诺和生产写回门禁，以及来源或秘密访问拒绝。
- 形成 `5` 个控制视图：可复现记录、文档提示注入、来源类型与外部增强、输出权限、未来候选与实际执行边界；`7` 条场景均保留业务线白箱复核要求。

## 专项验证结论形状

- 文档 evidence 和文档内潜在指令保持不可信、不可执行引用；`ids_rule_precedence_state` 固定为 `CONTROL_IDS_RULES_PREVAIL`，提示注入状态固定为拒绝。
- `internal_evidence`、`external_public_reference`、`model_reasoning` 与 `evidence_gap` 保持底层来源类型分离。无内部依据的场景只保留 `evidence_gap`，`external_augmentation_opinion` 不能伪装为内部经验或关闭缺口。
- 高风险工程建议、合同承诺和生产写回保持 `CONTROL_HUMAN_WHITEBOX_CONFIRMATION_REQUIRED_NO_AUTO_FINALIZATION`，最终结论固定为未发布。人工批准、模型调用、回答发布和生产写回均未发生。

## 本 phase 之外的运行时事项

真实文档读取、潜在指令识别或处理、查询、索引读取或切换、检索、Prompt 正文、provider 或模型选择和调用、模型 Token、来源类型绑定、外部增强显示、输出分类、人工确认、回答发布、生产写回、数据库连接、审计、持久化、Agent、OVH、生产和正式上传均属于后续授权范围。

## 验收与停止条件

- 场景模块只接受 P2 的固定投影；任一投影形状、IDS 规则优先、提示注入拒绝、来源类型、`evidence_gap` 或输出权限发生漂移时返回失败关闭、零场景和全零运行时计数。
- 聚焦白箱用例验证七条场景、`7×34` 字段形状、五个控制视图、三项任务包专项验证、来源语义、业务线白箱门禁、失败关闭、回退与零运行时边界。
- 本 run 止于 `IDS-STAGE102-P4-GATE`；P4、整阶段复审和 Stage103 保持未启动。
- 任何真实资料或运行时动作、任何不可回滚 schema 变更、任何跨 Stage 改动或测试原因不明的失败都会停止本 phase。
