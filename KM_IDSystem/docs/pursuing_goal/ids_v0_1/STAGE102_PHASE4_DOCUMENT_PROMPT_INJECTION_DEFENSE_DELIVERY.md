# Stage102 P4 · 文档内提示注入防护交付证据、回滚与中文反馈

## 目标与唯一依据

本 P4 只从 Stage102 P3 的七条固定、非业务、`reference-only` 场景派生交付控制记录。冻结 Stage102 任务包、Stage102 P1/P2/P3 工件与 Stage101 Review 构成唯一控制上下文；来源文档和业务线白箱人工复核继续承担业务事实权威。

控制交付记录不能替代来源文档，不能成为业务事实权威，也不能读取真实文档、原始元数据、查询、检索结果、Prompt 正文、回答、证据账本、审计日志、报告、数据库或物理索引。

## 固定交付几何

- P3 前序控制形状保持 `7` 条场景、每条 `34` 字段、共 `238` 个场景检查点；P2 的 `7×28`、四组、每条 `50` 字段、共 `350` 个前序控制检查点只作为控制引用。
- 回答样例、负向测试结果、prompt/version 记录、可复现日志和模型输出权限边界分别各 `7` 条，字段数依次为 `17/12/14/17/12`。
- prompt 回滚和模型配置回退说明固定为 `2` 条、每条 `12` 字段。
- P4 交付字段检查点固定为 `528`；记录只使用 `:control:stage102-p2:` 与 `:control:stage102-p4:` 不透明控制引用。

## 语义与业务线白箱门禁

- 文档内指令保持 evidence 候选且不可执行，IDS 规则保持优先。
- 无内部依据保持 `evidence_gap`，不伪装为内部经验；外部增强展示继续保留底层来源类型。
- 高风险工程建议、合同承诺和生产写回保持业务线白箱人工确认；人工确认未记录，最终结论未发布。
- 回答样例、负向结果、prompt/version 记录和可复现日志均为纯内存控制投影，不代表真实回答、测试、Prompt、模型配置或日志。

## 回滚与运行时边界

prompt 回滚和模型配置回退只声明未来控制目标。实际执行需要版本化依据、业务线白箱批准和可验证回退目标；本 P4 不执行回滚、模型配置回退、持久化写入、模型调用、模型 Token 消耗、Agent、OVH 或生产动作。

任何 P3 控制形状、文档内提示注入防护、`evidence_gap` 语义、输出权限、控制引用或运行时边界漂移均失败关闭并回到 `IDS-STAGE102-P4-GATE`。P4 完成后仅打开 `IDS-STAGE102-REVIEW-GATE`；不进入整阶段 Review、Stage103、正式全局上传、`main`、release 或生产。
