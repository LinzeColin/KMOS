# Stage113 P3 · 复核队列 Schema 专项异常场景与白箱门禁

## 本 run 的目标

本阶段只机械重放 Stage113 P2 的固定、非业务、reference-only 控制投影，形成五条可验证的专项场景记录：

1. 低质量 OCR 的复核操作控制；
2. 冲突资料的复核审计控制；
3. 撤回资料的重新复核控制；
4. 复核结果对 evidence trust level 与报告质量分的未来影响控制；
5. 外部增强不能替代内部证据的来源分离控制。

每条场景固定 52 个字段，五条共 260 个专项场景检查点；同时固定五个控制视图和五条业务线白箱处理记录。P2 前序控制形状保持为五条请求、每条 32 个输入字段、29 个 P1 控制引用、四组投影、每条 101 个字段、合计 505 个检查点。

## 控制语义

- 每条复核操作保留 actor、time、reason、old value、new value、review result 和 review audit 的未来控制引用。
- evidence trust level 与报告质量分只保留 before/after 和未来写回控制引用；本阶段不计算、修改或写回任何真实值。
- 撤回资料场景承接 P2 的 parsing failure / needs more material 控制形状，固定重新复核与归档引用，不读取或标记真实资料。
- 外部增强保持 external public reference 和 model reasoning 的来源分离，不能成为内部项目证据、不能替代证据绑定、不能关闭证据缺口。
- 五条业务线白箱处理记录均要求后续人工确认；本阶段不记录人工确认或最终业务结论。

## 输入、输出与单一权威

冻结 Stage113 任务包、Stage113 P1/P2 控制工件和 Stage112 Review 控制工件只构成工程控制上下文。来源文档、真实证据账本、已交付报告、既有审计日志和业务线白箱人工复核继续承担业务事实权威。本阶段不建立第二权威事实源。

输出只包括本范围说明、纯内存模块、合同、聚焦白箱用例、机器事实、治理投影、中文视图和本地 receipt。它们均为控制证据，不是复核队列、审计日志、证据账本、报告或业务结论。

## 零运行时边界

真实资料、OCR、冲突、撤回、解析、证据风险、复核队列、UI、审计、数据库、证据可信等级、报告质量分、报告状态、人工确认、模型、模型 Token、Agent、OVH、生产、正式全局上传和 push 均保持零执行。控制输入漂移、P2 形状漂移、审计字段缺失、影响控制缺失、外部增强越界或自动执行标志出现时，模块返回失败关闭结果且不输出场景、控制视图或白箱处理记录。

## 停止与回滚

本 run 止于 IDS-STAGE113-P4-GATE。P4 才能交付样例、审计日志或 UI 流程说明，整阶段 Review 与 Stage114 均保持未启动。

回滚只撤回本 P3 的范围说明、纯内存模块、合同、聚焦用例、machine run、机器事实、治理路线、事件、生成中文视图、变更记录和交接，恢复到 PASS_IN_MEMORY_REVIEW_QUEUE_SCHEMA_CONTROL_SLICE_RUNTIME_DISABLED。Stage113 P1/P2、Stage112 Review、冻结任务包、来源文档、真实证据账本、已交付报告、既有审计日志、数据库、GitHub、OVH 与应用状态保持既有边界。
