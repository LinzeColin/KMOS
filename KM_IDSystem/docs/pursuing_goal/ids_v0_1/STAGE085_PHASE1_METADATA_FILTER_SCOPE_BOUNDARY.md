# Stage085 Phase 1 · 元数据过滤范围、输入输出与边界确认

## 本轮目标

只将冻结的 `STAGE-085_元数据过滤.md` 与已复审的 Stage084 向量检索基线控制工件投影为一份静态工程合同。合同定义关键词检索、向量检索、元数据过滤、混合排序和检索轨迹的未来输入输出关系，明确不能只依赖向量相似度；不创建 PostgreSQL、FTS、BM25、pgvector、embedding、数据库连接、物理索引、检索结果或检索轨迹。

## 唯一权威与输入

- 冻结 Stage085 任务包是本阶段范围和验收的唯一来源。
- Stage084 Review 及其 P1--P4 已复审向量检索基线控制工件只作为前序控制证据；Stage085 不重定义、不替代或扩充其字段含义。
- 不建立第二权威事实源；来源文档、证据账本与业务线白箱人工复核仍是唯一业务权威。
- 不读取、打开、解析、复制、移动或修改真实资料、原始元数据、manifest、证据账本、审计日志、报告、数据库或物理索引。

## 静态输入输出合同

1. `query` 只由 query、语言、类型、请求 Top-K、向量模型／版本／维度／相似度度量和活动索引版本的不透明控制引用表示；不保存、选择或查询真实查询正文、模型或向量。
2. `filter` 固定文档类型、年份、项目、设备、资料状态和证据等级六类未来过滤维度，以及过滤状态；任一维度或资料状态控制引用缺失时，候选和选择均必须失败关闭。
3. `candidate`、`selected`、`score` 与 `active_index_version` 必须在同一控制链中；候选、选择和轨迹不得跨活动索引版本、元数据过滤合同、向量模型版本或相似度度量混用。
4. 关键词检索基线与向量检索基线均必须存在，向量相似度不得单独决定未来结果；未来混合排序必须保留关键词、向量、过滤匹配、混合分数和排序解释的控制字段。
5. `retrieval trace` 必须关联 query、filter、候选集合、选择集合、活动索引版本、向量模型版本、相似度度量和证据账本引用；它只描述未来审计形状，不读取证据账本或写入审计记录。
6. PostgreSQL full-text／BM25 风格关键词评分、pgvector 兼容接入、未来 embedding 生成和元数据过滤执行只作为后续授权 Phase 的工程前置；本 Phase 不创建 schema、索引、连接、模型选择、embedding、查询、过滤、评分、排序或 trace 写入。

## 本阶段不做

- 不实现或启动 PostgreSQL、FTS、BM25、pgvector、embedding、数据库 schema 或连接、物理索引、关键词查询、向量检索、元数据过滤、混合排序、Top-K 选择、检索轨迹或证据账本读取／写入。
- 不读取真实资料，不执行批量导入，不选择 provider 或模型，不消耗模型 Token，不调用外部 API，不执行 Agent。
- 不创建持久化 query、filter、candidate、selected、score、向量、检索轨迹、审计记录、缓存、队列、Operations、报告快照或已交付报告。
- 不启动 Stage085 P2、P3、P4、整阶段复审、OVH、生产、上传或推送。

## 验收与停止

本阶段只验收静态合同、聚焦用例、机器事实投影、中文生成视图与可撤回范围的一致性。任何真实资料访问、数据库 schema 或连接、索引构建、embedding、关键词或向量查询、元数据过滤、排序、检索轨迹读写、证据账本访问、持久化、模型调用、Agent、OVH、生产、上传或超出 Stage085 P1 的修改都会停止本阶段。

## 回退与下一门

只撤回本 P1 的范围说明、静态合同、聚焦用例、机器事实投影、治理路线、生成中文视图和本地回执，恢复到 `PASS_REVIEWED_VECTOR_RETRIEVAL_BASELINE_RUNTIME_DISABLED`。不影响 Stage084 Review、冻结任务包、真实资料、manifest、证据账本、审计日志、报告、数据库、索引、GitHub、OVH 或应用状态。下一步仅可在新的独立 run 进入 `IDS-STAGE085-P2-GATE`。
