# Stage101 P3 · RAG 可复现专项验证与异常场景

## 目标与唯一控制上下文

本 P3 只重放冻结 Stage101 任务包、Stage101 P1 静态合同、Stage101 P2 纯内存控制切片和 Stage100 Review 已复审控制工件。来源文档与业务线白箱人工复核继续承担业务事实权威；本文件、合同、场景模块和回执只描述控制形状，不建立第二权威事实源。

## 固定输入与场景形状

- 只接受 P2 的六条非业务、reference-only 控制输入，每条二十三字段、四组投影、每条四十五字段、共二百七十个源控制检查点。
- P3 将六条固定输入重放为六条纯内存场景，每条三十二字段，共一百九十二个场景检查点、五个控制视图和六条业务线白箱人工处理要求。
- 场景固定覆盖：安全摘要来源类型、`evidence_gap` 声明、检索文档指令拒绝、高风险工程建议、合同承诺和生产写回。
- query、index_version、prompt_version、model_provider、model_version、temperature、retrieval_context、selected_evidence 与模型推理只保留不透明未来控制引用；未来模型推理候选与实际模型调用、实际回答发布和实际审计写入分别记录。

## 三项任务包专项验证

1. 检索文档保持 evidence 身份；文档内提示词无法覆盖 IDS 规则，提示注入状态保持拒绝，最终结论保持未发布。
2. 无内部证据时只声明 `evidence_gap`，内部依据引用为空；外部公开参考与模型推理的展示标签保留底层来源类型，不伪装为内部经验。
3. 高风险工程建议、合同承诺和生产写回保持业务线白箱人工确认；自动最终结论、实际人工确认、实际回答发布与实际生产写回均为零值控制状态。

## 本 P3 明确边界

- 真实资料、原始元数据、manifest、物理索引、检索结果、提示词正文、回答、证据账本、审计日志、报告、数据库和持久化状态保持原有边界。
- 模型、外部 API、Agent、OVH、生产服务、GitHub 上传与推送保持后续门禁范围；模型 Token 与 Agent 执行计数为 `0`。
- 本 run 停在 P3，本地验收完成后才可在新的独立 run 进入 P4、整阶段 Review、后续 Stage、正式全局上传或生产部署。

## 验收与回滚

- 聚焦用例验证 P2 精确重放、三项专项场景、未来候选与实际调用分离、篡改失败关闭、单一权威、零运行时和 P4 门禁。
- P3 回滚只撤回本文件、P3 纯内存模块、合同、聚焦用例、machine run、机器事实、治理路线、生成中文视图、事件和交接，回到 `PHASE2_RAG_REPRODUCIBILITY_CONTROL_SLICE_RUNTIME_DISABLED`。
- 回滚保留 Stage101 P1/P2、Stage100 P1/P2/P3/P4/Review、冻结任务包、受保护资料、GitHub main/release、OVH 与应用状态。
- P3 完成本地验收后，下一步只可在新的独立 run 进入 `IDS-STAGE101-P4-GATE`。
