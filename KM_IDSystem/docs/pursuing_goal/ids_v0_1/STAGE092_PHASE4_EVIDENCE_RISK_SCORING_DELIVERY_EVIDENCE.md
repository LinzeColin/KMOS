# Stage092 P4 证据风险评分交付控制证据

## 1. 本阶段目标

本阶段从 Stage092 P3 的七类固定、非业务、`reference-only` 异常场景派生可测试、可回滚的交付控制记录：

- evidence ledger 样例；
- 证据等级报告；
- 撤回影响清单；
- 回归测试记录；
- 不可作为结论依据的证据类型；
- 证据降级说明；
- 撤回与恢复说明；
- 面向企业用户的克制中文反馈。

这些记录只在当前 Python 进程中存在，作为 P4 工程合同的控制投影。它们不写入真实 evidence ledger、报告、audit log、数据库或物理索引，也不替代来源文档、真实证据账本或业务线白箱人工复核。

## 2. 固定输入与交付形状

- P2 固定控制请求：`6` 条、每条 `27` 字段、`11` 组投影、每条 `97` 字段、合计 `582` 个控制检查点；
- P3 固定场景：`7` 类、每类 `32` 字段、合计 `224` 个场景检查点；
- P4 交付控制记录：evidence ledger 样例 `7×14`、等级报告 `7×13`、撤回影响 `7×13`、回归记录 `7×14`、不可作为结论依据类型 `7×11`、降级说明 `4×10`、撤回／恢复说明 `2×11`，合计 `517` 个交付字段检查点；
- 中文反馈：`4` 条固定、控制性说明。

P3 的无内部证据、低 OCR、旧版本、冲突、撤回、恶意资料与低等级伪装高可信结论均保持原有处置语义。撤回影响只声明未来报告状态复核；低 OCR、旧版本、冲突和撤回保持降级候选；恶意资料保持隔离候选；低等级证据保持高可信结论拒绝状态；所有实际处置均需业务线白箱人工审批。

## 3. 业务规则边界

冻结任务包没有定义风险权重、阈值或业务判定公式。本阶段不生成风险分值、可信等级变更、自动结论、自动降级、自动撤回、自动恢复或报告状态更新。上述业务规则仍由业务线白箱 owner、来源文档与真实证据账本裁定。

## 4. 失败关闭与停止条件

P4 在以下情况返回固定失败状态：P3 输出缺失或形状漂移、运行时信号出现、控制引用失去不透明性、无内部证据路由丢失、降级／撤回／隔离／低等级拒绝语义漂移、交付记录形状漂移、写入信号出现、自动结论或自动处置开放、或整阶段 Review 已被提前进入。

需要真实资料、业务公式、真实 ledger／报告／审计日志、数据库、检索、模型、Agent、OVH 或生产运行时立即停止在本 P4 合同边界。

## 5. 验证与回滚

聚焦验证运行 `test_stage092_evidence_risk_scoring_delivery`；最终关联验证覆盖 Stage092 P4/P3/P2/P1、Stage091 Review/P1--P4、Stage090 Review/P1--P4、Stage089 Review 与 Stage088 Review。

回滚只撤回本 P4 的范围说明、交付控制模块、合同、聚焦用例、machine run、事件、机器事实、治理路线与生成中文视图，恢复到 `PASS_EVIDENCE_RISK_SCORING_CONTROLLED_SCENARIOS_RUNTIME_DISABLED`。Stage092 P1--P3、Stage091 Review/P1--P4、冻结任务包、真实资料、manifest、真实 evidence ledger、报告、audit log、数据库、GitHub、OVH 与应用状态保持原状。
