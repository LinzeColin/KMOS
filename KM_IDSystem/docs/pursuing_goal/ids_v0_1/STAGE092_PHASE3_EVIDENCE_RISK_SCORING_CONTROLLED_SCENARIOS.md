# Stage092 Phase3 · 证据风险评分专项验证与异常场景

## 本轮范围

本 P3 只以冻结 `STAGE-092_证据风险评分.md`、Stage092 P1/P2 合同和已复审的
Stage091 控制工件为合同上下文。在内存中重放 P2 的六条固定、非业务、
`reference-only` 控制投影，验证异常场景、失败关闭和业务线白箱人工处理边界。

P2 的固定形状保持为六条请求、每条 27 个输入字段、11 组投影、每条 97 个
投影字段、共 582 个源控制检查点。P3 不新增风险权重、阈值或业务判定公式；这些
规则继续由业务线白箱 owner 明确后才可进入后续受控阶段。

## 固定异常场景

1. 无内部证据：保留 `evidence_gap`，不伪装为 `evidence_id`。
2. 低 OCR：保持降级候选，不接受为结论依据。
3. 旧版本：保持降级候选，不接受为结论依据。
4. 冲突资料：保持降级候选，不接受为结论依据。
5. 撤回资料：声明未来报告状态影响引用，不更新真实报告。
6. 恶意资料：保持隔离候选，不自动处置。
7. 低等级伪装高可信：D 等级控制引用不得支撑高可信结论。

每个场景只产生 32 个不透明控制字段，共 224 个场景字段检查点。所有场景都要求
业务线白箱人工处理，且不产生真实审批、报告状态更新、可信等级变更或业务结论。

## 失败关闭与边界

- P2 固定形状、零运行时、控制引用或关键结论关联偏离时立即返回明确失败状态。
- 不读取、打开、复制、保留、写入、查询或解析真实资料、原始元数据、fixture、
  manifest、检索结果、证据账本、审计日志、回答、报告、数据库或物理索引。
- 不执行来源、OCR、版本、复核、冲突或风险评估，不计算风险分值，不执行撤回、
  隔离、恢复、报告状态更新、模型调用、模型 Token、Agent、OVH、生产或正式上传。
