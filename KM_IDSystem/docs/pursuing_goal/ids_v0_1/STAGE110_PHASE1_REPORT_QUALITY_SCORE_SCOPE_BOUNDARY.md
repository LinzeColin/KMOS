# Stage110 Phase 1 · 报告质量评分范围与边界

## 当前目标

依据冻结 `STAGE-110_报告质量评分.md`，定义报告内部证据覆盖率、引用完整率、外部增强占比、证据缺口和报告质量评分的未来控制形状。报告证据绑定、外部增强章节、人工确认项、报告快照、报告影响分析、PDF 引用来源与 data/index/evidence/model/generated_at 快照均保持为业务线白箱控制引用。

本 Phase 形成可执行、可测试、可回滚的静态工程合同。来源文档、真实证据账本、已交付报告与业务线白箱人工复核继续承担业务事实权威；本合同只保存不透明控制标签，不形成第二权威事实源。

## 固定控制范围

- 报告证据绑定、关键结论 `evidence_id/evidence_gap`、证据等级、PDF 引用来源与页码、外部增强章节及其底层来源类型、人工确认项与业务线白箱确认门的未来控制引用。
- `data/index/evidence/model/generated_at` 五项报告生成快照，以及资料更新、资料撤回、证据降级、索引版本变化、受影响报告和报告状态影响的未来控制引用。
- 内部证据覆盖率、引用完整率、外部增强占比、证据缺口数、质量指标定义、质量公式、权重、阈值、评分和评分说明全部保留为未来控制引用。
- 质量公式、权重、阈值、评分解释、报告状态调整、人工确认和最终业务结论均由业务线白箱 owner 在后续授权流程中定义、复核和记录。

## 输入、输出与单一权威

输入仅为冻结 Stage110 任务包与已复审的 Stage109 报告影响分析控制工件。输出仅为本范围说明、静态合同、聚焦白箱用例和零运行时本地回执。

所有以 `_ref` 结尾的字段均为不透明控制标签。真实报告、PDF、引用内容、资料变化、证据等级、快照值、指标值、质量公式、权重、阈值、质量分数、报告状态、人工确认、审计记录和业务结论均由业务线白箱 owner 在后续授权流程中处理。

## 停止条件

真实资料、原始元数据、外部参考、证据账本、已交付报告和 PDF 均由受保护边界管理。读取或写入真实质量指标、质量公式、权重、阈值、质量分数、报告状态、报告/PDF、引用、快照、审计或数据库，以及模型调用、模型 Token、Agent、OVH、生产激活、正式全局上传与 Stage110 P2 均属于后续独立授权范围。

## 验收与回滚

聚焦用例验证 40 个未来控制引用、4 个冻结质量指标、质量定义／公式／权重／阈值／评分／说明的白箱控制边界、关键结论的 `evidence_id/evidence_gap` 独立性、PDF 引用来源与页码、五项生成快照、资料变化的未来报告状态影响、外部增强来源边界、人工确认、失败关闭和全零运行时边界。

回滚只撤回本 Phase 的范围说明、静态合同、聚焦用例、回执、机器事实投影、治理路线、事件与生成中文视图，恢复到 `PASS_REVIEWED_REPORT_IMPACT_ANALYSIS_RUNTIME_DISABLED`。Stage109 P1--P4/Review、冻结任务包、来源文档、真实证据账本、已交付报告、审计日志、数据库、GitHub main/release、OVH 与生产状态保持原状。

下一独立 run 才可进入 `IDS-STAGE110-P2-GATE`。
