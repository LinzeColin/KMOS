# Stage082 Phase 2 · 旧索引保留策略控制切片边界

## 目标

在不读取任何 IDS 业务资料、不访问保护目录、不建立第二权威事实源的前提下，实现一个固定输入、纯内存、`reference-only` 的旧索引保留策略控制切片。切片投影未来索引版本、候选后台构建、影子隔离、冒烟输入输出、未应用切换、未应用回滚资格、最低上一活动版本保留和失败关闭的旧索引清理资格；它不构建、查询、切换、回滚、清理或持久化真实索引。

## 唯一依据与范围

- 冻结任务包：`STAGE-082_旧索引保留策略.md`。
- 已完成前置：Stage082 P1 静态旧索引保留策略合同，以及 Stage081 Review/P1--P4 已审核影子索引控制工件。
- 引用只用于固定控制标签和字段形状；不读取上述文件所指向的真实索引、数据库、导入资料、原始元数据或业务线内容。
- 不新增业务规则、文档范围、嵌入模型、索引版本、实际保留数量、实际清理时点或实际回滚窗口的权威事实；业务线白箱人工处理只以未来未记录前置表达。

## 固定控制输入

输入严格固定为五条 `:control:stage082-p2:` 控制请求。每条请求的 `chunk_count` 为 `0`，所有引用均为不透明控制标签，候选、活动、上一活动和影子索引引用两两隔离。每条索引版本控制记录固定记录冻结任务包要求的七个字段：`index_version`、`index_kind`、`lifecycle_state`、`document_scope_ref`、`chunk_count`、`embedding_model_ref`、`source_import_ref`。

五个非业务控制场景分别覆盖：

1. 已通过冒烟门的候选切换资格，仍不执行切换，旧索引清理因保留参数未设值而关闭。
2. 后台构建未完成，活动版本保持不变。
3. 影子冒烟测试失败，切换关闭且活动版本保持不变。
4. 计划原子切换失败，活动版本保持不变。
5. 上一活动版本已按最低数量保留，但回滚窗口、清理时点、额外保留数量和业务线白箱批准均未设值，因此回滚与旧索引清理保持关闭。

每条控制请求只固定最低 `minimum_retained_previous_active_version_count=1`。额外保留数量、回滚窗口、清理时点和业务线白箱批准均以 `UNCONFIGURED` 控制标签表示，绝不推断为实际政策或实际批准。

## 控制投影与失败关闭

切片只在内存中投影索引版本记录、候选构建与影子隔离、活动指针、冒烟测试输入输出、未应用的原子切换候选、未应用的回滚请求资格、保留策略字段和旧索引清理资格。候选构建未完成、冒烟输入缺失、冒烟失败、候选或影子不隔离、计划切换失败、上一活动版本未保留、额外保留数量未设值、回滚窗口未设值、清理时点未设值或业务线白箱批准未记录，均必须关闭相应切换、回滚或清理；活动指针投影始终保持原活动版本，旧活动版本连续服务。

## 严格禁止

不得读取或写入真实索引、数据库、文件、网络、外部 API、模型、Agent、OVH 或生产环境；不得启动后台构建、实际冒烟、检索、并发检索、切换、回滚、旧索引清理或自动业务写入；不得创建持久化记录、实际 manifest、冒烟日志、切换记录、回滚证明、Operations 或报告快照；不得上传 GitHub 或 push。P3、P4、整阶段审查和 Stage083 均不在本 run 范围内。
