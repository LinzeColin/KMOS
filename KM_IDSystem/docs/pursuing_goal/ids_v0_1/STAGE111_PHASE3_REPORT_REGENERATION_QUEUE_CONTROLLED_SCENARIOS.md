# Stage111 P3 · 报告重新生成队列专项验证与异常场景

## 目标与入口

- 任务：`IDS-V0_1-STAGE111-P3`
- 入口门禁：`IDS-STAGE111-P3-GATE`
- 下一门禁：`IDS-STAGE111-P4-GATE`
- 依据：冻结 `STAGE-111_报告重新生成队列.md`、Stage111 P1/P2 控制工件与 Stage110 Review 已复审的报告质量评分控制工件。

本阶段机械重放 P2 的五条固定、非业务、`reference-only` 控制投影。来源文档、真实证据账本、已交付报告与业务线白箱人工复核继续承担业务事实权威；本阶段形成专项控制场景，不形成第二权威事实源。

## 固定验证范围

P2 固定形状保持为：五条控制请求、每条三十二个输入字段、承接 P1 的三十个控制引用、四组投影、每条八十八个投影字段、共四百四十个前序控制检查点。P3 固定形成：

- 五条场景、每条四十四个字段、共二百二十个场景检查点；
- 五个控制视图与五条业务线白箱处理记录；
- 五条场景均保留业务线白箱人工确认门禁，最终结论保持未记录、未发布；
- 十五类失败关闭状态与四条中文反馈。

五条场景逐条覆盖冻结任务包的 P3 验证项：

| P2 控制请求 | P3 控制结论 |
| --- | --- |
| 引用资料更新 | 关键结论保持 `evidence_id_ref`，报告证据绑定、证据等级、引用来源与页码保持控制引用。 |
| 资料撤回 | 关键结论保持 `evidence_gap_ref`，资料撤回只形成未来报告状态与队列复核要求。 |
| 证据降级 | 关键结论保持 `evidence_id_ref`，证据降级只形成未来报告状态与队列复核要求。 |
| 证据冲突 | 关键结论保持 `evidence_gap_ref`，证据冲突只形成未来报告状态与队列复核要求。 |
| 索引版本变化 | 关键结论保持 `evidence_id_ref`，索引版本变化只形成未来报告状态与队列复核要求。 |

所有场景同时验证外部增强保留 `external_public_reference` 与 `model_reasoning` 的底层来源语义，不能写成内部项目依据、替代证据绑定或关闭证据缺口。

## 控制边界

场景模块只重放 P2 的控制标签。它不读取真实资料、原始元数据、外部参考、报告、PDF、证据账本、审计日志、数据库或物理索引；不生成报告、PDF、引用、快照、影响结果、质量分数、队列条目或审计记录；不调用模型、Agent、外部 API、OVH 或生产服务。

资料撤回、证据降级、证据冲突和索引版本变化只表达未来报告状态与队列复核控制，不读取、更新、发布、重新生成或撤回真实报告。业务线白箱人工确认与最终业务结论保持后续授权范围。

## 失败关闭与回退

P2 控制形状、零运行时边界、不透明引用、关键结论绑定、报告状态与队列控制、外部来源分离或白箱确认门禁发生漂移时，P3 返回失败报告：不形成场景、控制视图或业务记录，所有运行时计数保持零，运行时标志保持 `false`。

回退只撤回本 P3 的范围说明、纯内存场景模块、合同、聚焦用例、machine run、机器事实投影、治理路线、事件、生成中文视图与交接，返回 `PASS_IN_MEMORY_REPORT_REGENERATION_QUEUE_CONTROL_SLICE_RUNTIME_DISABLED`。Stage111 P1/P2、Stage110 Review、冻结任务包、来源文档、真实证据账本、已交付报告、数据库、GitHub、OVH 与应用状态保持原状。

## P4 前置条件

P3 本地验收完成后停在 `IDS-STAGE111-P4-GATE`。P4 只可从本阶段固定控制场景派生 metadata-only 交付证据、报告样例、报告快照、报告质量评分、影响分析、模板限制、人工确认要求、重新生成／撤回说明和中文反馈，继续保持单一权威事实源、业务线白箱人工复核与全零运行时边界。
