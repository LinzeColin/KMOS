# Stage091 Phase 3 · 证据缺口处理异常场景受控验证

## 本轮目标

本阶段只在内存中重放 Stage091 P2 的六条固定、非业务、`reference-only` 控制投影，验证无内部证据、低 OCR、旧版本、冲突资料、撤回资料、恶意资料和低等级伪装高可信结论七类异常场景。撤回场景只声明未来报告状态影响引用；每条场景继续要求业务线白箱人工处理。

## 唯一权威与输入

- 冻结 Stage091 任务包、Stage091 P1 静态合同、Stage091 P2 纯内存控制切片与已复审 Stage090 从检索捕获证据控制工件构成唯一合同上下文。
- P3 只读取 P2 模块函数返回的固定控制投影。控制投影不包含业务资料、来源正文、真实路径、真实 OCR、真实版本、真实风险或实际报告内容。
- 来源文档、真实 evidence ledger 和业务线白箱人工复核继续承担业务事实权威；P3 场景只是本地验证控制记录，不能替代业务事实或形成第二权威事实源。

## 固定受控场景

1. 无内部证据：保持 `evidence_gap_ref`，关键结论进入业务线白箱人工复核。
2. 低 OCR：保持低可信降级候选与人工复核。
3. 旧版本：保持过期降级候选与人工复核。
4. 冲突资料：保持冲突降级候选与人工复核。
5. 撤回资料：保持撤回降级候选，并声明未来报告状态影响引用。
6. 恶意资料：保持疑似投毒隔离候选与人工复核。
7. 低等级伪装：D 等级控制引用进入高可信结论拒绝状态。

每条场景固定 32 个控制字段。场景结果只存在于函数返回值中；证据等级、报告状态、业务结论、审计记录和持久化状态保持原状。

## 阶段边界

- 本阶段只处理固定控制引用、场景状态、失败关闭和白箱处理要求。
- 真实资料、原始元数据、fixture、manifest、检索结果、evidence ledger、audit log、报告、数据库和物理索引保持受保护状态。
- 检索、证据捕获、OCR 评估、版本比较、冲突裁决、风险评分、可信等级变更、撤回执行、投毒处置、报告状态更新、模型、Agent、OVH、生产、P4、Review 与正式上传保持在后续授权范围。

## 验收与停止

验收覆盖 P2 六条控制请求、十组投影、468 个 P2 字段检查点、七条异常场景、224 个场景字段检查点、撤回报告影响引用、低等级伪装拒绝、失败关闭、业务线白箱人工处理与零运行时边界。任何真实资料或 evidence ledger 访问、数据库 schema 或连接、持久化、实际检索／缺口／风险／撤回／投毒处理、模型、Agent、OVH、生产或超出 P3 的修改都会停止本阶段。

## 回退与下一门

回退范围仅为本 P3 的阶段说明、纯内存场景模块、聚焦用例、机器事实投影、治理路线、中文视图和本地回执；回退目标为 `PHASE2_EVIDENCE_GAP_HANDLING_CONTROL_SLICE_RUNTIME_DISABLED`。Stage091 P1/P2、Stage090 Review、冻结任务包、真实资料、manifest、检索、evidence ledger、audit log、报告、数据库、索引、GitHub、OVH 和应用状态保持原状。下一步仅可在新的独立 run 进入 `IDS-STAGE091-P4-GATE`。
