# Stage095 Phase 3 · 证据回归测试专项验证与异常场景

## 本轮范围

本 P3 只以冻结 `STAGE-095_证据回归测试.md`、Stage095 P1/P2 合同和 Stage094
Review 已复审控制工件作为合同上下文。在内存中重放 P2 的六条固定、非业务、
`reference-only` 控制投影，验证异常场景、失败关闭和业务线白箱人工处理边界。

P2 固定保持六条请求、每条 21 个输入字段、六组投影、每条 58 个投影字段、共 348
个源控制检查点。P3 不定义或计算风险公式、阈值、可信等级分配、撤回、降级、恢复、
投毒处置或业务判定；这些规则继续等待业务线白箱 owner 在后续受控阶段明确。

## 固定异常场景

1. 无内部证据：保留 `evidence_gap`，不伪装为 `evidence_id`。
2. 低 OCR：保持降级候选，不接受为关键结论依据。
3. 旧版本：保持降级候选，不接受为关键结论依据。
4. 冲突资料：保持降级候选，不接受为关键结论依据。
5. 撤回资料：声明未来报告状态影响引用，不更新真实报告。
6. 恶意资料：保持隔离候选，不自动处置。
7. 低等级伪装高可信：D 等级控制引用不得支撑高可信结论。

每个场景只产生 32 个不透明控制字段，共 224 个内部场景字段检查点。所有场景都要求
业务线白箱人工处理，且不产生真实审批、报告状态更新、可信等级变更、风险计算、撤回、
降级、恢复、投毒处置或业务结论。

## 失败关闭与边界

- P2 固定形状、零运行时、控制引用、关键结论关联或场景语义偏离时立即返回明确失败状态。
- 不读取、打开、复制、保留、写入、查询或解析真实资料、原始元数据、fixture、manifest、
  检索结果、证据账本、审计日志、回答、报告、数据库或物理索引。
- 不执行来源、OCR、版本、复核、冲突或风险评估，不执行真实可信等级变更、撤回、隔离、
  恢复、报告状态更新、模型调用、模型 Token、Agent、OVH、生产、上传或推送。
