# Stage089 Phase 3 · 证据账本异常场景受控验证

## 本轮目标

只在内存中重放 Stage089 P2 的六条固定、非业务、reference-only 控制投影，验证无内部证据、低 OCR、旧版本、冲突、撤回和恶意资料六类异常场景。撤回只形成未来报告状态影响引用，低等级证据伪装高可信结论只形成拒绝控制状态；不读取或改变真实证据、报告或可信等级。

## 唯一权威与输入

- 冻结 Stage089 任务包、Stage089 P1 静态合同、Stage089 P2 纯内存控制切片及已复审 Stage088 工件是本 P3 唯一合同上下文。
- P3 仅从 P2 内建的六条控制投影读取不透明引用；它们不包含业务资料、来源正文、真实路径、真实 OCR、真实版本、真实风险或报告内容。
- 来源文档、真实证据账本与业务线白箱人工复核仍是唯一业务权威；P3 场景不能替代或创建权威事实。

## 固定受控场景

1. 无内部证据：必须保留证据缺口引用，关键结论不得自动采纳。
2. 低 OCR：必须维持低可信降级候选，不得自动升格。
3. 旧版本：必须维持过期降级候选，不得自动采纳。
4. 冲突资料：必须维持冲突降级候选，不得自动裁决。
5. 撤回资料：必须维持撤回降级候选，并只声明未来报告状态影响引用，不更新真实报告。
6. 恶意资料：必须维持疑似投毒隔离候选，不执行真实隔离或恢复。
7. 低等级伪装：D 等级控制引用不得支撑高可信结论，必须失败关闭。

每个场景都保持业务线白箱人工处理；所有关联仅在函数返回值中存在。

## 本阶段不做

- 不读取、打开、解析、复制、移动、修改或删除真实资料、原始元数据、fixture、manifest、evidence ledger、audit log、报告、数据库或物理索引。
- 不执行真实 OCR 质量评估、版本比较、冲突裁决、撤回、报告状态更新、投毒检测、隔离、恢复、风险计算、可信等级变更或业务结论。
- 不调用 provider 或模型，不消耗模型 Token，不执行 Agent、外部 API、OVH、生产、上传或推送。
- 不启动 Stage089 P4、Review 或 Stage090。

## 验收与停止

验收仅覆盖 P2 控制形状、七条固定异常控制场景、撤回报告影响引用、低等级伪装拒绝、失败关闭、业务线白箱人工处理和零运行时边界。任何真实资料、证据账本、数据库、报告状态、模型、Agent、OVH、生产或超出 P3 的访问或动作都会停止本阶段。

## 回退与下一门

回退只撤回本 P3 的范围说明、纯内存场景模块、聚焦用例、机器事实投影、治理路线、生成中文视图和本地回执，恢复到 PASS_EVIDENCE_LEDGER_CONTROL_SLICE_RUNTIME_DISABLED。不影响 Stage089 P1/P2、冻结任务包、真实资料、manifest、evidence ledger、audit log、报告、数据库、索引、GitHub、OVH 或应用状态。下一步仅可在新的独立 run 进入 IDS-STAGE089-P4-GATE。
