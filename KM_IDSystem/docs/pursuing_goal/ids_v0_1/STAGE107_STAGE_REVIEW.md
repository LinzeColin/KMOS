# Stage107 · 人工确认事项章节整阶段机械复审

## 目标与入口

- 任务：`IDS-V0_1-STAGE107-REVIEW`
- 入口门禁：`IDS-STAGE107-REVIEW-GATE`
- 后续门禁：`IDS-STAGE108-P1-GATE`

本 Review 只在内存中机械聚合静态合同与纯内存控制报告，复核报告人工确认事项、关键结论 `evidence_id/evidence_gap` 二选一、引用来源与页码、data/index/evidence/model/generated_at 五项快照、报告状态影响、外部增强来源分离、业务线白箱人工确认、模板限制和 P4→P3 回退保持一致。来源文档、真实证据账本与业务线白箱人工复核继续承担业务事实权威。

## 权威、运行时与业务线白箱边界

- 每项关键结论保持 `evidence_id` 或 `evidence_gap` 的严格二选一；引用来源、引用页码、索引版本和五项快照只保留不透明控制引用。
- 外部增强保持 `external_public_reference` 与 `model_reasoning` 的底层来源语义，不能成为内部项目依据，也不能替代或关闭 `evidence_gap`。
- 资料撤回、证据降级和索引版本变化保持未来报告状态影响控制；报告模板限制、人工确认和最终结论保持业务线白箱门禁，人工确认未记录、最终结论未发布。
- 报告重新生成和撤回只保留版本化、可验证的 P3 回退目标；Review 不执行真实重新生成、撤回、报告状态修改、质量评分、影响分析或审计写入。
- 本 Review 只处理控制元数据。真实资料、报告、PDF、证据账本、审计日志、数据库、模型、模型 Token、Agent、OVH、生产、正式全局上传与推送均不属于本 phase 的执行范围。

## 失败关闭、停止条件与回滚

- P1--P4 身份、固定形状、控制引用、证据绑定、来源语义、报告状态影响、人工确认、回退或全零运行时边界发生漂移时，Review 返回失败关闭报告，后续门禁保持 `IDS-STAGE107-REVIEW-GATE`。
- 对业务来源、原始元数据、真实报告、PDF、证据账本、审计、数据库、物理索引、模型、Agent、OVH、生产、正式上传、推送或 Stage108 的任何动作都会停止本 phase。
- 回滚只撤回本 Review 的说明、纯内存复审模块、合同、聚焦用例、machine run、治理投影与生成中文视图，恢复到 `PASS_HUMAN_CONFIRMATION_ITEMS_DELIVERY_EVIDENCE_RUNTIME_DISABLED`。Stage107 P1--P4、Stage106 Review、冻结任务包、来源文档、真实证据账本、已交付报告、审计日志、数据库、GitHub、OVH 与应用状态保持原状。
