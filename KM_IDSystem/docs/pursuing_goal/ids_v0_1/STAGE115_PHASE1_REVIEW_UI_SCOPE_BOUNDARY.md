# Stage115 · 复核 UI Phase 1 范围、输入输出与控制边界

## 目标与入口

- 任务：`IDS-V0_1-STAGE115-P1`
- 入口门禁：`IDS-STAGE115-P1-GATE`
- 后续门禁：`IDS-STAGE115-P2-GATE`
- 冻结输入：Stage115 任务包与 Stage114 Review 已复审的复核工作流控制工件。

本 Phase 固定人工产品入口与 IDS 系统运营入口的未来复核 UI 控制形状。界面以中文呈现复核队列、复核原因、状态、审计引用、影响预览和业务线白箱门禁；界面不承载机器内部细节、真实队列项、真实复核结果、真实证据可信等级、真实报告质量分或业务结论。

## P1 固定复核 UI 控制合同

- 输入与输出只包含 future-control reference：复核队列项、触发类型、状态、中文复核原因、actor、time、转换原因、old value、new value、review result、审计、证据可信等级前后、报告质量前后、报告状态影响、重新复核、归档与业务线白箱门禁。
- 低 OCR 置信度、资料冲突、解析失败和证据风险必须分别保留指向未来 `pending_review` 的控制路由；本 Phase 不评估真实 OCR、冲突、解析或证据风险。
- 状态集固定为 `pending_review`、`confirmed`、`rejected`、`needs_more_material`、`archived`；中文状态文本固定为“待复核”“已确认”“已拒绝”“需补资料”“已归档”。`submit_for_review`、`confirm`、`reject`、`request_more_material`、`archive` 保留为未来交互动作控制标签；具体允许的状态转移、归档时机、重新复核与例外处理继续由业务线白箱人工复核授权。
- 中文 UI 固定显示“复核队列”“复核详情”“审计引用”“影响预览”“业务线白箱门禁”五个静态控制分区。中文复核原因保持可理解、克制、面向企业用户的控制标签；机器内部实现细节保持在工程控制层。
- 每次未来复核操作保留 `actor`、`time`、`reason`、`old_value`、`new_value`、`review_result` 与审计控制引用。复核结果只指向未来 evidence trust level、报告质量分和报告状态影响控制，业务事实、等级、分数和最终结论继续由业务线白箱人工复核形成。
- 外部增强保持外部来源身份，不能成为内部项目证据、替代证据绑定或关闭 evidence gap。

## 单一权威与运行时边界

- 冻结 Stage115 任务包与 Stage114 Review 控制工件构成本 Phase 的唯一工程控制上下文；来源文档、真实证据账本、已交付报告、既有审计日志与业务线白箱人工复核继续承担业务事实权威。
- 本 Phase 产物是范围说明、静态 UI 控制合同、聚焦用例、治理投影和本地回执。真实资料、OCR、冲突、解析、证据风险、复核队列、复核工作流、复核 UI 渲染、复核审计、证据可信等级、报告质量分、报告状态、数据库、人工确认、模型 Token、Agent、OVH、生产和正式上传保持后续授权范围。
- 本 run 不创建 UI 页面、队列、工作流实例、状态转换、审计、schema migration、数据库或持久化记录；运行计数保持零。

## 验收、停止与回滚

- 聚焦用例必须验证十九个 future UI 控制引用、四类未来入队路由、五个固定状态、五个未来动作标签、五个中文 UI 控制分区、中文复核原因、actor/time/reason/old/new 审计控制、复核结果对证据可信等级与报告质量／状态控制的未来引用、外部增强来源分离、业务线白箱门禁和零运行时边界。
- 缺失 Stage114 Review 控制、任一触发、任一状态、任一 UI 分区、中文原因、动作标签、审计必填引用、证据可信等级或报告影响控制，或者出现实际 UI、队列、工作流、人工确认、审计写入、数据库写入、第二权威、模型、Agent、OVH、生产或提前进入 P2 时，合同以失败状态关闭并停留在 `IDS-STAGE115-P1-GATE`。
- 回滚只撤回本 P1 的范围说明、静态 UI 控制合同、聚焦用例、machine run、治理投影、中文视图与交接，恢复 Stage114 Review 的本地零运行时状态；来源文档、真实证据账本、已交付报告、既有审计日志、数据库、GitHub、OVH 与应用状态保持既有边界。
