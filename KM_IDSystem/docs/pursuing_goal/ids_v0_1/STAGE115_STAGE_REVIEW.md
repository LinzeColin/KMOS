# Stage115 · 复核 UI 整阶段机械复审

## 目标与入口

- 任务：IDS-V0_1-STAGE115-REVIEW
- 入口门禁：IDS-STAGE115-REVIEW-GATE
- 后续门禁：UNASSIGNED_SUCCESSOR_GATE
- 冻结输入：Stage115 任务包、Stage115 P1--P4 控制工件，以及 Stage114 已复审复核工作流控制工件。

本 Review 机械聚合 P1 静态合同、P2 纯内存控制切片、P3 专项场景与 P4 metadata-only 交付控制证据。复审确认中文复核 UI 的固定形状、单一权威边界、审计控制、证据可信等级与报告质量／状态影响、外部增强来源分离、业务线白箱门禁、失败关闭和 P4→P3 回退目标保持一致。

## 固定复审形状

- P1：19/4/5/5/5/7/20/4，即未来控制引用／入队触发／固定状态／动作标签／中文控制分区／审计引用／失败关闭／中文反馈。
- P2：5×23/19/4×117/585，即五条非业务、reference-only 控制请求、四组投影与总检查点。
- P3：5×47=235/5/5/5/15/5，即专项场景、控制视图、业务线白箱处理、白箱确认、失败关闭与中文反馈。

## 复审约束

- 冻结任务包与 Stage115 P1--P4、Stage114 Review 控制工件只承载工程控制语义；来源文档、真实证据账本、已交付报告、既有审计日志和业务线白箱人工复核继续承担业务事实权威。
- actor、time、reason、old value、new value、review result、review audit、重新复核和归档保持审计控制引用；证据可信等级、报告质量和报告状态影响保持未来控制。
- 低质量 OCR、资料冲突、撤回资料、证据风险和外部增强来源分离保持控制场景。外部增强保持独立来源，不能成为内部证据、替代内部证据或关闭 evidence gap。
- 复核状态转换、审计、人工确认、最终结论、证据与报告写回、P4 回退和重新复核保持业务线白箱后续授权。复审模块只读取冻结控制工件并输出纯内存结果。
- 真实资料、OCR、复核 UI、队列、审计、数据库、模型 Token、Agent、OVH、生产、未分配后继和正式全局上传保持零执行。

## 失败关闭与回滚

- P1--P4 合同、控制输出、字段形状、单一权威、审计、影响、来源语义、白箱门禁、回退目标或运行时边界发生漂移时，模块返回固定失败状态并停留在 IDS-STAGE115-REVIEW-GATE。
- 回滚只撤回本 Review 的说明、纯内存模块、合同、聚焦用例、machine run、机器事实、治理路线、事件和生成中文视图，恢复 PASS_REVIEW_UI_DELIVERY_EVIDENCE_RUNTIME_DISABLED。
- Stage115 P1--P4、Stage114 Review、冻结任务包、来源文档、真实证据账本、已交付报告、既有审计日志、数据库、GitHub、OVH 和应用状态保持原有边界。

## 验收与停止条件

- 聚焦用例复审 P1--P4 的固定形状、复核审计、证据可信等级与报告质量／状态影响、外部增强来源分离、业务线白箱门禁、失败关闭和 P4→P3 回退；Stage005、两组 Batch 门禁、中文视图和治理投影共同形成本地验收证据。
- 当前 run 完成后止于 UNASSIGNED_SUCCESSOR_GATE。后继 Stage 需要在新的冻结任务包和独立授权 run 中定义。
