# Stage115 · 复核 UI Phase 2 受控最小切片

## 目标与前置

- 任务：`IDS-V0_1-STAGE115-P2`
- 入口门禁：`IDS-STAGE115-P2-GATE`
- 后续门禁：`IDS-STAGE115-P3-GATE`
- 前置：Stage115 P1 静态中文复核 UI 合同与 Stage114 Review 控制工件。

本 Phase 将 P1 的未来控制引用投影为唯一允许的五条非业务、`reference-only` 纯内存控制请求。每条请求固定 `23` 个输入字段：场景、控制绑定、状态、动作与 P1 的 `19` 个控制引用。该切片提供可测试的控制投影，不承载真实复核对象、状态、审计、证据可信等级、报告质量、报告状态或业务结论。

## 固定控制请求与最小切片

- 五条请求分别覆盖低 OCR 置信度进入待复核、资料冲突确认、解析失败需补资料、证据风险拒绝，以及外部增强归档的来源边界；前四条保持 P1 要求的四类未来入队路由，第五条保持外部增强来源分离与归档动作标签。
- 状态集固定为 `pending_review`、`confirmed`、`rejected`、`needs_more_material`、`archived`；动作集固定为 `submit_for_review`、`confirm`、`reject`、`request_more_material`、`archive`。这些值是控制标签，实际状态转移、重新复核和归档时机由业务线白箱人工复核授权。
- 每条请求派生四组纯内存投影：中文复核 UI／队列／动作、复核审计、证据可信等级与报告影响控制、中文原因与外部增强来源边界。字段形状为 `39/27/26/25`，每条共 `117` 个字段，五条共 `585` 个检查点。
- 审计投影保留 `actor`、`time`、`reason`、`old_value`、`new_value`、`review_result`、重新复核与归档的未来引用。影响投影只保存 evidence risk、evidence trust level、报告质量和报告状态的未来控制标签，实际写回由业务线白箱门禁承接。
- 中文 UI 投影提供企业可理解的复核原因、状态、动作与五个控制分区；它不渲染界面、不发送反馈、不创建用户可见记录。

## 单一权威、运行时边界与失败关闭

- 冻结 Stage115 任务包、Stage115 P1 静态合同与 Stage114 Review 控制工件构成工程控制上下文；来源文档、真实证据账本、已交付报告、既有审计日志与业务线白箱人工复核继续承担业务事实权威。
- 输入严格等于五条固定控制请求才会投影。任意字段漂移返回 `CONTROL_INPUT_MISMATCH`，输出零条投影、零运行时计数与全关闭运行边界。
- 本 Phase 不读取、创建、移动、修改或写入真实资料、OCR、冲突、解析、证据账本、报告、审计日志、队列、UI、数据库、人工确认、模型 Token、Agent、OVH、生产或 GitHub；每项实际计数为零。
- P3 才验证低质量 OCR、冲突资料、撤回资料、外部增强替代内部证据等专项场景。P2 完成本地验收后停止在 `IDS-STAGE115-P3-GATE`。

## 验收与回滚

- 聚焦用例验证五条控制输入、四类必经路由、五个状态和动作、四组投影、中文 UI 分区、审计引用、未来影响写回、中文原因、外部增强来源分离、业务线白箱门禁、输入漂移失败关闭和零运行时边界。
- 回滚只撤回 P2 的范围说明、纯内存模块、静态合同、聚焦用例、machine run、机器事实、治理路线、事件和生成中文视图，恢复 `PASS_REVIEW_UI_CONTRACT_RUNTIME_DISABLED`；P1、Stage114 Review、任务包、来源文档、真实证据账本、报告、审计日志、数据库、GitHub、OVH 与应用状态保持既有边界。
