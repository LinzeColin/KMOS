# Stage112 P4 · 报告导出审计交付证据、回滚与中文反馈

## 目标与输入边界

- 任务：`IDS-V0_1-STAGE112-P4`
- 入口门禁：`IDS-STAGE112-P4-GATE`
- 下一门禁：`IDS-STAGE112-REVIEW-GATE`
- 依据：冻结 `STAGE-112_报告导出审计.md`、Stage112 P1/P2/P3 控制工件与 Stage111 已复审的报告重新生成队列控制工件。

本 phase 只从 P3 的五条固定、非业务、`reference-only` 场景派生 metadata-only 交付控制记录。来源文档、真实证据账本、已交付报告、既有审计日志与业务线白箱人工复核继续承担业务事实权威；交付元数据只描述控制状态，不形成第二权威事实源。

## 交付控制形状

- 报告样例、报告快照、报告质量评分、报告影响分析、报告模板限制与业务线白箱人工确认各 `5` 条，字段形状依次为 `17/13/13/15/14`。
- 报告重新生成与撤回说明各 `1` 条，共 `2` 条、每条 `14` 字段。
- 五组各 5 条控制记录、两条生命周期说明、共 388 个 metadata-only 检查点、17 类失败关闭和 4 条中文反馈。

报告样例保留 `actor`、`time`、`report_id`、`evidence_snapshot` 与报告导出审计控制引用，关键结论继续严格关联 `evidence_id_ref` 或 `evidence_gap_ref`。报告快照保留报告、报告状态影响、data/index/evidence/model/generated_at 的控制引用；质量评分只保留质量定义、公式、权重、阈值、评分与说明的交付控制引用；影响分析保留资料撤回、证据降级和索引版本变化的未来报告状态与导出审计复核控制。

## 任务包专项边界

- 资料撤回、证据降级和索引版本变化只表达未来报告状态、质量、快照和导出审计复核要求，真实报告状态保持不变。
- 报告样例、快照、质量评分和影响分析均为 metadata-only 控制记录；不计算指标或分数，也不渲染报告、PDF 或引用。
- 外部增强保留 `external_public_reference` 与 `model_reasoning` 的来源语义，不能成为内部项目依据，不替代证据绑定，不关闭 `evidence_gap`。
- 模板限制、人工确认和最终结论保持业务线白箱门禁；人工确认未记录，最终结论未发布。
- 重新生成与撤回说明固定指向版本化、可验证的 P3 回退目标；两项生命周期动作均未执行。

## 运行边界、失败关闭与回滚

交付模块只处理控制引用：它不读取、列举或处理真实资料、原始元数据、外部参考、报告、PDF、证据账本、既有审计日志、数据库或物理索引；不生成报告、PDF、引用、快照、评分、影响分析、状态、审计或业务结论；模型 Token、Agent、OVH、生产与正式全局上传保持零执行。

P3 场景形状、运行时边界、关键结论绑定、导出审计身份、报告状态影响、外部增强来源分离、白箱确认、控制引用或交付形状发生漂移时，模块返回失败关闭报告：零交付记录、全零运行时计数和全 false 运行时标志。

回滚只撤回本 P4 的范围说明、纯内存交付模块、静态合同、聚焦用例、machine run、机器事实投影、治理路线、事件、生成中文视图与交接，返回 `PASS_REPORT_EXPORT_AUDIT_CONTROLLED_SCENARIOS_RUNTIME_DISABLED`。Stage112 P1/P2/P3、Stage111 Review、冻结任务包、来源文档、真实证据账本、已交付报告、既有审计日志、数据库、GitHub、OVH 与应用状态保持原状。

本 run 止于 `IDS-STAGE112-REVIEW-GATE`；整阶段 Review、Stage113、正式全局上传、OVH 与生产继续由后续独立门禁承接。
