# Stage112 · 报告导出审计 Phase 1 范围与控制边界

## 目标与入口

- 任务：IDS-V0_1-STAGE112-P1
- 入口门禁：IDS-STAGE112-P1-GATE
- 后续门禁：IDS-STAGE112-P2-GATE
- 冻结输入：Stage112 任务包与 Stage111 报告重新生成队列整阶段复审控制工件。

本 Phase 固定报告导出审计的未来控制形状。每个未来报告导出必须关联 actor、time、report_id、evidence_snapshot 四类控制引用，并保留报告证据绑定、外部增强来源分离、人工确认、报告快照、影响分析、质量评分、PDF 引用来源和 data/index/evidence/model/generated_at 生成快照。

## P1 固定控制合同

- 报告导出审计记录只包含未来控制引用与标签；actor、time、report_id、evidence_snapshot 均不承载真实值。
- 报告关键结论保持 evidence_id 或 evidence_gap 的严格二选一；证据等级、引用来源与页码、外部增强底层来源类型和业务线白箱确认保持独立控制引用。
- PDF 报告的未来交付合同要求显示引用来源；外部增强章节保持外部来源身份，不能替代内部报告证据绑定或关闭 evidence_gap。
- 报告快照与 data/index/evidence/model/generated_at 五项生成快照保持分离控制；报告影响分析、质量评分、导出格式、导出目的地、审计状态、保留、重新生成和撤回保持未来可审阅控制引用。
- 业务线白箱确认是未来真实导出、人工确认、重新生成和撤回的授权入口。

## 单一权威与运行时边界

- 冻结 Stage112 任务包与 Stage111 Review 控制工件构成本 Phase 的唯一工程控制上下文；来源文档、真实证据账本、已交付报告、原有审计日志和业务线白箱人工复核继续承担业务事实权威。
- 本 Phase 产物是范围说明、静态合同、白箱用例、治理投影和本地回执。真实资料、外部参考、报告、PDF、引用内容、快照、actor、时间、report_id、审计记录、数据库、人工确认、模型 Token、Agent、OVH、生产和正式上传保持后续授权范围。
- 本 run 不创建导出、PDF、审计、数据库或持久化记录；运行计数保持零。

## 验收、停止与回滚

- 聚焦用例必须验证四类导出审计必填控制引用、报告证据绑定、PDF 引用来源、外部增强来源分离、人工确认、五项生成快照、影响与质量控制，以及零运行时边界。
- 缺失前序 Stage111 Review 控制、任一导出审计必填控制引用、报告证据绑定、PDF 引用来源、人工确认、快照、影响、质量、审计保留控制，或者发现实际导出、PDF 生成、审计写入、数据库写入、第二权威、模型、Agent、OVH、生产或提前进入 P2 时，合同以失败状态关闭并停留在 IDS-STAGE112-P1-GATE。
- 回滚只撤回本 P1 的范围说明、静态合同、聚焦用例、machine run、治理投影、中文视图与交接，恢复 Stage111 Review 的本地零运行时状态；来源文档、真实证据账本、已交付报告、既有审计日志、数据库、GitHub、OVH 与应用状态保持原有边界。
