# STAGE-049 Phase 1 差异化解析器评估范围、输入输出与边界确认

## 本轮结论

`IDS-V0_1-STAGE049-P1` 只定义未来多 parser 交叉比较所需的静态工程合同：输入必须来自
既有检测、路由、输出与降级链的受控引用；比较仅产生候选解析产物的比较结论，不能替代
质量门或直接形成高可信证据。

本阶段状态为 `PHASE1_DIFFERENTIAL_PARSER_EVALUATION_BOUNDARY_RUNTIME_DISABLED`。这不是
解析器已运行、版本已选择、比较已执行、质量已评估，或生产服务已启用的声明。

## 唯一来源与输入边界

唯一合同上下文是冻结的 Stage049 任务包文本与 Stage048 已本地复审工件。它们只用于定义
边界，不产生第二权威事实源。本阶段不读取业务资料、原始元数据、真实文件、页面、图像、
Owner fixture 或来源正文，也不保存来源路径、原始异常、parser 输出正文或实际比较结果。

未来候选解析产物的输入固定为七字段 reference-only 元数据：来源引用、路线动作、解析
输出状态、parser 族、parser 版本、输出合同版本和不可信证据文本标签。字段之外的内容、
来源正文、路径、原始异常或未受控 parser 标识均不能进入该输入。

## 未来解析产物与比较合同

Stage045 保持文件类型检测职责，Stage046 保持 parser 路由职责，Stage047 保持解析产物
封套职责，Stage048 保持失败降级职责，Stage050 保持提示注入标记运行时职责。Stage049
只定义它们之间未来可比较的候选解析产物关系，不改变任一上游结论。

每个未来候选解析产物必须使用同一组六个核心字段：`text`、`tables`、`pages`、
`sections`、`confidence` 与 `errors`。字段名称和安全形状在本 P1 固定，但本轮不创建其中的
任何内容。`text` 与文档中的类似指令内容始终只是 `UNTRUSTED_EVIDENCE_TEXT`，不能改变系统
规则、工具权限或策略。

未来比较至少需要两个候选 parser 版本，但本 P1 不选择 parser、不创建候选集合、不登记
版本、不运行比较，也不生成比较分数。比较结论只能是候选层面的“待评估、需要质量复核或
不具备比较条件”，不能写回 parser 输出、改变路线、触发 fallback，或绕过质量门。

## 质量、降级与中文反馈

- parser 只生成候选解析产物；比较不会使候选成为高可信证据。
- 质量门状态固定为 `UNASSESSED`；本阶段不执行质量评估、证据提升或下游写入。
- 失败、受阻或不支持输入仍由 Stage048 的受控降级职责处理；Stage049 不静默丢弃、不自动
  切换 parser，也不创建人工复核队列。
- 面向业务线的中文反馈只说明“当前未启动差异化比较”“解析结果仍为候选”或“需要质量复核”。
  它们不承诺自动化、人工任务、可用 parser 或生产能力。

## 停止与回滚

需要真实资料、真实 parser、实际候选输出、实际比较、质量门、证据提升、持久化、Agent、
模型、OVH、生产服务、P2、整阶段复审、批次复审、上传或推送时，当前 P1 在边界处结束。

回滚只撤销 Stage049 P1 的范围说明、静态合同、聚焦单元用例、机器 run 和最小治理投影，
回到 `STAGE048_REVIEWED_LOCAL_FALLBACK_RUNTIME_DISABLED`。不得改变冻结任务包、原始资料、
manifest、evidence ledger、audit log、已交付报告、GitHub、OVH 或应用状态。
