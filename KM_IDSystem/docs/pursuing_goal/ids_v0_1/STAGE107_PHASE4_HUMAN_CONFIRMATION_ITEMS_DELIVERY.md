# Stage107 P4 · 人工确认事项章节交付证据、回滚与中文反馈

## 本 phase 的目标

依据冻结 Stage107 人工确认事项章节任务包、Stage107 P1/P2/P3 控制工件与已复审 Stage106 外部增强意见控制工件，从 P3 的六条固定、非业务、`reference-only` 场景派生报告样例、报告快照、报告质量评分、影响分析、模板限制、业务线白箱人工确认、报告重新生成和撤回的交付控制记录。

## 单一权威与输入边界

- 冻结 Stage107 任务包、Stage107 P1/P2/P3 与 Stage106 Review 控制工件构成唯一控制上下文。
- 来源文档、真实证据账本与业务线白箱人工复核继续承担业务事实权威；本 phase 的交付 metadata 仅描述控制状态，不形成第二权威事实源。
- 输入只来自 P3 的六条固定控制场景。每个引用都是 `reference-only` 控制标签，不含业务事实、来源正文或路径、真实报告、PDF、快照、评分、影响分析、审计记录或业务结论。
- 本 phase 不读取、列举、提取、分类或处理业务资料、原始元数据、真实外部参考、模型推理、真实报告、PDF、证据账本、审计日志、数据库、物理索引或已交付报告。

## 交付证据形状

- 六条报告样例控制记录，每条 `17` 个字段；六条报告快照控制记录，每条 `13` 个字段；六条报告质量评分控制记录，每条 `13` 个字段。
- 六条报告影响分析控制记录，每条 `15` 个字段；六条报告模板限制与业务线白箱人工确认控制记录，每条 `14` 个字段；两条报告重新生成和撤回控制记录，每条 `14` 个字段。
- 总计 `460` 个 metadata-only 字段检查点。它们交付可测试的工程合同，保持报告样例未渲染、快照未持久化、评分未计算、影响分析未执行、人工确认未记录、重新生成与撤回未执行。

## 任务包专项控制

- 报告样例保持关键结论与 `evidence_id` 或 `evidence_gap` 的严格二选一，并保留证据等级、引用来源、引用页码和索引版本控制引用。
- 报告快照保持报告、索引版本和报告状态影响的控制关联；质量评分保持证据绑定、报告状态影响和业务线白箱复核条件。
- 资料撤回、证据降级和索引版本变化保持报告状态影响控制形状；外部增强保留外部参考与模型推理的来源语义，不能成为内部项目依据、不能替代或关闭 `evidence_gap`。
- 报告模板限制与六类业务线白箱人工确认均形成明确控制门禁，最终结论保持未发布。
- 报告重新生成与撤回说明固定指向可验证的 P3 回退目标，要求版本化依据和业务线白箱确认。

## 运行边界、停止条件与中文反馈

- 交付模块只处理控制标签，不生成或修改真实报告、PDF、引用、快照、评分、影响分析、状态、审计或业务结论。
- 模型 Token、Agent、OVH、生产、数据库、外部 API、正式全局上传和推送保持零执行。
- 中文反馈只说明控制状态、人工前置条件和回退目标，面向企业用户保持清楚、克制。
- P3 输出形状、运行时边界、关键结论绑定、报告状态影响、外部增强来源分离、白箱确认、控制引用或交付形状发生漂移时，模块返回失败关闭报告：零交付记录、全零运行时计数和全 false 运行时标志。
- 本 run 止于 `IDS-STAGE107-REVIEW-GATE`；Stage107 Review、Stage108、OVH、生产和正式全局上传保持后续门禁。

## 回滚

回滚只撤回本 P4 的范围说明、纯内存交付模块、静态合同、聚焦用例、机器事实投影、治理路线、事件、生成中文视图、本地回执与交接，返回 `PASS_HUMAN_CONFIRMATION_ITEMS_CONTROLLED_SCENARIOS_RUNTIME_DISABLED`。冻结任务包、Stage107 P1/P2/P3、Stage106 Review、来源文档、真实证据账本、已交付报告、审计日志、数据库、GitHub、OVH 与应用状态保持原状。
