# Stage090 Phase 3 · 从检索捕获证据异常场景受控验证

## 本轮目标

本阶段在内存中重放 Stage090 P2 的六条固定、非业务、reference-only 控制投影，并验证无内部证据、低 OCR、旧版本、冲突、撤回、恶意资料与低等级伪装高可信结论七类场景。撤回场景输出未来报告状态影响引用；业务线白箱人工处理保持为每条场景的必经控制。

## 唯一权威与输入

- 冻结 Stage090 任务包、Stage090 P1 静态合同、Stage090 P2 纯内存控制切片、Stage089 Review 与前序 evidence schema 合同构成唯一合同上下文。
- P3 从 P2 内建控制投影读取不透明引用。控制投影不包含业务资料、来源正文、真实路径、真实 OCR、真实版本、真实风险或报告内容。
- 来源文档、真实证据账本与业务线白箱人工复核保持业务事实权威；P3 场景作为验证控制记录。

## 固定受控场景

1. 无内部证据：保留 evidence_gap 引用，关键结论进入白箱人工复核。
2. 低 OCR：维持低可信降级候选与人工复核。
3. 旧版本：维持过期降级候选与人工复核。
4. 冲突资料：维持冲突降级候选与人工复核。
5. 撤回资料：维持撤回降级候选，输出未来报告状态影响引用。
6. 恶意资料：维持疑似投毒隔离候选与人工复核。
7. 低等级伪装：D 等级控制引用进入高可信结论拒绝状态。

每条场景保留 32 个控制字段。场景结果仅存在于函数返回值，报告状态、证据等级与业务结论保持原状。

## 阶段边界

- 本阶段处理固定控制引用、场景状态、失败关闭和白箱处理要求。
- 真实资料、原始元数据、fixture、manifest、检索结果、evidence ledger、audit log、报告、数据库和物理索引保持受保护状态。
- 检索、证据捕获、OCR 评估、版本比较、冲突裁决、风险评分、可信等级变更、撤回执行、投毒处置、报告状态更新、模型、Agent、OVH、生产与上传保持在后续授权范围。

## 验收与停止

验收覆盖 P2 六条控制请求、十组投影、462 个 P2 字段检查点、七条异常场景、224 个场景字段检查点、撤回报告影响引用、低等级伪装拒绝、失败关闭、业务线白箱人工处理与零运行时边界。下一门为 IDS-STAGE090-P4-GATE。
