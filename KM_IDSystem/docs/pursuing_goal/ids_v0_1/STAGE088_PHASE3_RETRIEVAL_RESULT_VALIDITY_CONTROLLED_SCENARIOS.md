# Stage088 Phase 3 · 检索结果有效性门禁受控场景

## 目标与唯一事实源

本文件仅把冻结 Stage088 任务包和已完成的 Stage087 Review、Stage088 P1/P2 控制合同机械投影为八个纯内存场景。不建立第二权威事实源；任务包、前序已审核合同和未来获授权的业务线白箱人工复核仍分别保持其原有权威边界。

本 Phase 的通过只表示固定控制引用、失败关闭和人工门禁形状一致，不表示任何资料、检索结果、排序、Top-K、索引版本或结果有效性正确。

## 输入与运行时边界

- 只重放 Stage088 P2 的六条固定、非业务、reference-only 控制投影及其 9 组记录形状。
- 不读取真实资料、来源正文、原始元数据、fixture、manifest、证据账本、审计日志或报告；不读取其路径。
- 不连接数据库，不执行 PostgreSQL、FTS/BM25、pgvector、embedding、关键词检索、向量检索、材料牌号匹配、设备型号匹配、标准号匹配、语义相似计算、过滤、混合排序、Top-K、trace 读写、旧索引服务访问或结果有效性判定。
- 不写入持久化记录、参数、索引、证据账本、审计日志、业务结论或运行时配置。
- 不选择或调用模型、Agent、OVH、生产、GitHub 上传或推送；不消耗模型 Token，生产运行保持零 Agent 与零模型 Token。

## 八个固定受控场景

1. 关键词基线；
2. 材料牌号关键词；
3. 设备型号混合检索；
4. 标准号混合检索；
5. 语义相似混合检索；
6. 六维过滤组合；
7. Top-K、排序解释和结果有效性；
8. 旧索引服务的检索轨迹版本。

材料牌号、设备型号、标准号和语义相似均只代表场景类别，绝不携带业务值。八个场景各自只保留 P2 产生的不透明控制引用，并固定要求业务线白箱人工复核。

## 受控输出与门禁

每个场景固定 33 个字段，覆盖 query、filter、candidate、selected、评分、排序解释、trace、活动索引版本、证据账本、结果有效性门禁和人工处理状态；8 个场景合计 264 个字段检查点。结果有效性保持 CONTROL_RESULT_VALIDITY_NOT_EVALUATED，所有结果有效性门禁状态保持 CONTROL_VALIDITY_GATE_PENDING_HUMAN_WHITEBOX_REVIEW。

以下任一情况必须失败关闭：P2 输出不是固定控制形状、出现运行时信号、引用不透明性丢失、关键词或向量基线缺失、vector-only 路线、六维过滤组合不完整、活动索引版本或 trace 链不一致、Top-K 或排序解释缺失、结果有效性链缺失、门禁不再待人工白箱复核，或场景预期不符。

本 Phase 成功后仅可进入 IDS-STAGE088-P4-GATE；不进入 Stage088 P4、Stage088 Review、Stage089、OVH、生产或上传。

- 中文反馈只说明控制边界、未评估状态和下一项人工动作；不得暗示自动决策或业务真实性。
- 回滚仅撤回本 Phase 的范围说明、合同、纯内存模块、聚焦测试、P3 治理和派生回执；保留 Stage088 P1/P2、Stage087 已审核工件、冻结任务包、真实资料、fixture、manifest、证据账本、审计日志、数据库、索引、GitHub、OVH 与应用状态。
