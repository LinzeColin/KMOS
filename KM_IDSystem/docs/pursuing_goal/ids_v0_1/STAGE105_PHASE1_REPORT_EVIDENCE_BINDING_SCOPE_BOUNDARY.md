# Stage105 Phase 1 · 报告证据绑定范围与边界

## 当前目标

依据冻结 `STAGE-105_报告证据绑定.md`，固定报告关键结论的未来证据绑定形状：每项关键结论未来必须关联 `evidence_id_ref` 或 `evidence_gap_ref`，并保留引用来源、索引版本、生成时间、报告快照、影响分析、质量评分、外部增强章节和人工确认项的控制引用。

本 Phase 只形成可执行、可测试、可回滚的静态工程合同。它不建立第二权威事实源；来源文档、真实证据账本和业务线白箱人工复核继续承担业务事实权威。

## 固定控制范围

- 报告关键结论、`evidence_id`/`evidence_gap`、证据等级、引用来源与页码、索引版本和生成时间的未来引用。
- `data/index/evidence/model snapshot` 五项未来快照形状。
- 外部增强章节保留 `external_public_reference` 与 `model_reasoning` 的底层来源类型，不能写成内部项目依据，也不能关闭或替代 `evidence_gap`。
- 报告未来必须含业务线白箱人工确认项；人工确认、业务使用和最终结论仍由后续授权和人工复核决定。
- 报告快照、报告状态影响分析、质量评分、导出审计、模板限制、重新生成和撤回的未来控制引用。
- PDF 报告必须显示引用来源；本 Phase 不创建 PDF、报告或引用内容。

## 输入、输出与单一权威

输入仅为冻结 Stage105 任务包与已复审的 Stage104 RAG 负向测试控制工件。输出仅为本范围说明、静态合同、聚焦白箱用例和零运行时回执。

合同中的所有 `*_ref` 是不透明控制标签，不是资料、证据、报告、审计记录、快照或业务结论。证据等级规则、报告质量公式、阈值、报告状态规则和最终人工确认记录均等待业务线白箱 owner 的后续授权。

## 停止条件

以下任一动作属于后续授权范围：读取真实资料、证据账本、已交付报告或 PDF；生成、导出、发布或撤回报告/PDF；生成引用；保存 data/index/evidence/model snapshot；写入报告状态、质量评分、影响分析、导出审计、数据库或持久化存储；调用模型、消耗模型 Token、运行 Agent、连接 OVH、激活生产、推送正式全局上传；进入 `IDS-STAGE105-P2-GATE`、P3、P4、整阶段 Review 或 Stage106。

## 验收与回滚

聚焦用例验证 24 个未来控制引用、关键结论的 `evidence_id` 或 `evidence_gap` 要求、PDF 引用来源要求、五项快照、外部增强语义、人工确认、报告生命周期引用、失败关闭和全零运行时边界。

回滚只撤回本 Phase 的范围说明、静态合同、聚焦用例、回执、机器事实投影、治理路线、事件、生成中文视图和交接，恢复到 `PASS_REVIEWED_RAG_NEGATIVE_TEST_RUNTIME_DISABLED`。Stage104 P1--P4/Review、冻结任务包、来源文档、真实证据账本、已交付报告、审计日志、数据库、GitHub main/release、OVH 和生产状态保持原状。

下一独立 run 才可进入 `IDS-STAGE105-P2-GATE`。
