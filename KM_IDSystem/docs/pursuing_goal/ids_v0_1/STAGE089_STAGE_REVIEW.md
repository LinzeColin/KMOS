# Stage089 证据账本 Schema 整阶段机械复审

## 目标

只在内存中机械复审冻结 Stage089 的 P1--P4 合同、P2/P3/P4 控制输出、失败关闭、业务线白箱人工处理与 P4→P3 可回退边界。复审确认 evidence_id、document_id、chunk_id、fact_id、report_id、source_type、evidence_grade、证据缺口、风险、撤回和投毒防护始终只是控制引用，不形成第二权威事实源或业务结论。

## 复审范围与固定形状

- P1：evidence 10、relation 8、gap 5、risk 8、revocation 7、知识库投毒防护 8、关键结论绑定 7 个静态字段，23 类失败关闭，A/B/C/D/E 等级保持完整；
- P2：6 条固定、非业务、reference-only 控制请求，24 个输入字段、10 组投影、每请求 74 个字段、共 444 个字段检查和 23 类失败关闭；
- P3：7 类无内部证据、低 OCR、旧版本、冲突、撤回、恶意和低等级伪装高可信结论场景，32 个字段、224 个字段检查、7 条业务线白箱人工处理与 15 类失败关闭；
- P4：7/7/7/7/7 条样例、等级报告、撤回影响、回归、不可作为结论依据类型，4 条降级说明、2 条撤回／恢复说明、4 条中文反馈、517 个字段检查和 18 类失败关闭。

## 不可突破边界

- 只读取本仓冻结任务包与既有控制工件；不读取、打开、复制、写入、查询、删除、评估、执行或回退真实资料、来源正文、原始元数据、manifest、真实 evidence ledger、报告、audit log、数据库、物理索引或业务事实。
- 不执行数据库 schema 或连接、检索证据捕获、实际 OCR／版本／冲突评估、风险计算、可信等级变更、撤回、恢复、投毒处置、报告状态更新、provider／模型、模型 Token、Agent、OVH、生产、上传或推送。
- 来源文档、真实证据账本与业务线白箱人工复核仍是唯一权威；复审输出不得替代来源、成为业务事实、自动作出结论或触发业务处置。
