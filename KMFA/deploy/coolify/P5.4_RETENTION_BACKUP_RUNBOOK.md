# P5.4 保留、备份、恢复与明确删除 Runbook

适用范围：KMFA schema v4。该 Runbook 每季度至少执行一次，并在 schema、数据库 backend、对象
provider、备份格式或删除 worker 发生实质变化后追加执行。通过证据最长有效 93 天。

本文件不授权当前中间 Phase 切生产。只有 S05 整体复审通过后，才可按本文启用生产删除。

## 不变量与停止条件

- 默认无时间到期任务；只有持有有效 session、workspace recovery secret、明确确认文本和
  `Idempotency-Key` 的用户请求才能建立删除任务。首次接受后只允许相同四要素精确回放同一请求；
  回放不恢复 session，任一字段不匹配必须失败。
- App 服务不得拥有 `KMFA_S3_LIFECYCLE_*`；删除 worker 不暴露端口，并使用独立、prefix-scoped
  list/get/delete-version 凭据。生产 active lifecycle 必须使用 S3-compatible backend；
  legacy filesystem 无法隔离删除权限，必须保持 paused。测试专用
  `KMFA_LIFECYCLE_ALLOW_LEGACY_FILESYSTEM_DELETE=1` 禁止进入生产 compose/secret。
- worker claim 租约为 10 分钟；活跃租约不得并发重入，只有超过租约且无心跳的任务可 crash
  recovery。public purge SLA 以 adapter 实际完成时间为准；`public_purge_sla_exceeded` 必须在
  对象删除前 fail closed、退出自动 due 队列、保留事件并升级人工处置。
- 当前 schema 的隔离恢复必须达到：fixture `100%`、`invariant_failures=0`，并实际测量 RPO/RTO。
  未通过或证明超过 93 天时，删除 API fail closed。
- legal hold 存在时不得开始不可逆删除。若已进入 `deleting/deleted`，迟到的 hold 必须报冲突并立即
  升级人工处置，不得伪报已保全。
- 备份必须包含 DB 行、对象字节和对象 tombstone。只有 metadata、同机 named volume、快照名称或
  manifest 而没有深 hash 对应字节，不算备份。
- 私有备份目录可能含用户数据，不得提交 Git、上传 CI artifact、粘贴到工单或写入公共 receipt。
- 任一证明缺失、hash 不一致、目标环境不空、public cache/index adapter 不可用、legal hold 冲突，
  立即停止；保持 `KMFA_LIFECYCLE_MODE=paused`。

## 每次备份

1. 记录待运行的完整 tuple：`source_commit`、不可变 image digest、DB backend、对象 provider、UTC
   时间。凭据只在 Coolify Secret/受控 env-file 中提供，不作为命令参数。
2. 将 App 与 worker 的 `KMFA_LIFECYCLE_MODE` 置 `paused`，将
   `KMFA_CONSISTENCY_STATE_MODE` 置 `paused` 并重部署。确认新上传被暂停；既有恢复、读取和下载仍可用。
3. 在执行 full backup 的短窗口内停止所有 App writer 和 lifecycle worker。不要删除或重建任何
   volume/bucket。确认没有 `consistency_operations` 处于非 `converged/isolated` 状态；命令会再次
   机械检查并拒绝 pending operation。destination、bundle、objects 目录和 blob 都不得是 symlink。
4. 通过当前候选镜像创建新目录；目标父目录必须是权限受控的独立加密介质：

```bash
python3 -m app.backup_restore backup \
  --kind full \
  --destination /backup/kmfa/full-YYYYMMDDTHHMMSSZ \
  --artifact-identity SOURCE_COMMIT/IMAGE_DIGEST \
  --backup-id backup_YYYYMMDD_full_0001
```

5. 恢复 App writer 时保持删除 `paused`。按批准频率创建真实 logical incremental；`--parent` 必须按
   full → incremental 的完整顺序重复提供：

```bash
python3 -m app.backup_restore backup \
  --kind incremental \
  --parent /backup/kmfa/full-YYYYMMDDTHHMMSSZ \
  --destination /backup/kmfa/incremental-YYYYMMDDTHHMMSSZ \
  --artifact-identity SOURCE_COMMIT/IMAGE_DIGEST \
  --backup-id backup_YYYYMMDD_incremental_0001
```

6. 只有目录内 `COMPLETE` 与 canonical `manifest.json` SHA-256 一致时才复制。将完整目录原样复制到
   独立故障域的加密、访问审计、版本锁定存储；复制后重新计算 manifest、database delta 与全部 blob
   hash。同主机目录只能作为 staging，不得宣称满足灾难恢复。

## 季度隔离恢复演练

1. 新建无公网路由的隔离环境：空 PostgreSQL 数据库、空对象 bucket/prefix、空 state root，运行与
   备份 identity 对应的镜像。严禁把 restore 指向生产 DB/bucket。
2. 同时保持两个写入 mode 为 `paused`，按顺序恢复完整链：

```bash
python3 -m app.backup_restore restore \
  --chain /backup/kmfa/full-YYYYMMDDTHHMMSSZ \
  --chain /backup/kmfa/incremental-YYYYMMDDTHHMMSSZ \
  --incident-at YYYY-MM-DDTHH:MM:SSZ
```

   `--incident-at` 必须是带时区的真实事件时间且不得早于最终 recovery point；否则 RPO 证据无效并
   fail closed。

3. 校验命令输出 `status=pass`、`invariant_failures=0`，并记录 `measured_rpo_ms`、
   `measured_rto_ms`。随后必须通过真实 App 路径验证标准 fixture：
   recovery → project/progress/score/financial/task → attachment download → SHA-256；期望与恢复数必须
   完全相同。
4. 在隔离环境做负测：错误 token、错误 recovery secret、legal hold、published-then-delete、
   cache/index purge、对象删除一次故障后重试、provider 全版本/删除标记归零。再生成含删除 tombstone
   的 incremental，并恢复到第二个空环境；被删 workspace、业务行、对象和旧 recovery capability
   均不得复活。
5. 同一镜像可先运行全合成 Oracle 复核实现：

```bash
python KMFA/app/e2e/retention_backup_restore_flow.py \
  --image IMAGE_TAG_OR_DIGEST \
  --state-dir EMPTY_PRIVATE_TEMP_DIR \
  --out-dir PUBLIC_SAFE_REPORT_DIR \
  --prefix kmfa-p54-quarterly \
  --source-commit FULL_SOURCE_COMMIT
```

6. 两名复核者确认备份 identity、manifest hash、fixture 计数、RPO/RTO、无 invariant failure、
   public purge SLA、legal hold 和不复活结果。只有全部通过，才在生产 DB 仍为 quiesced/paused 时记录
   gate；数值必须来自本次演练输出：

```bash
python3 -m app.backup_restore record-proof \
  --backup-id BACKUP_ID \
  --manifest-sha256 MANIFEST_SHA256 \
  --expected-fixtures EXPECTED_COUNT \
  --restored-fixtures RESTORED_COUNT \
  --invariant-failures 0 \
  --measured-rpo-ms RPO_MS \
  --measured-rto-ms RTO_MS \
  --artifact-identity-hash ARTIFACT_IDENTITY_HASH
```

## 灰度启用与回滚

S05 Stage Review 批准后才执行：

1. 保持 App 删除 `paused`，先启用 `lifecycle` profile；核验写 backend 是 S3-compatible、worker
   无公网端口、App 容器环境不存在 lifecycle 凭据、legacy test override 不存在、当前 schema proof
   有效、无 legal hold 冲突。
2. 在受控窗口将 App 与 worker 的 `KMFA_LIFECYCLE_MODE` 同时置 `active`。先用单一合成 workspace
   完整执行删除并核验 public purge、DB tombstone、对象所有 provider versions、旧 recovery 失效和
   append-only lifecycle evidence，再扩大可用范围。
3. 异常时先将 lifecycle worker scale-to-zero，随后把 App/worker mode 恢复 `paused`。保留 DB、
   object、backup、outbox、trace、lifecycle events 和所有 named volume；禁止 `down -v`、schema
   downgrade 或删证据。`deleting` target 可在修复后按持久状态安全续跑。
4. 误删或 provider 故障时保持暂停，从 object version/最近闭合 backup chain 恢复到新隔离环境，
   对账通过后再做 forward-fix 切换。不得直接覆盖仍在运行的生产 DB/bucket。

公共 receipt 只记录 tuple、manifest hash、计数、RPO/RTO、PASS/FAIL 与复核人；不得包含 DSN、bucket
key、workspace ID、文件名、recovery capability、对象 key 或备份内容。
