# App 数据每日异地备份（Owner 2026-07-26 批准「现在就接上」）

## 你担心的问题（对的）
KMFA 全云端后,**App 自己产生的记录**(你点"拍板"、导报告、每步审计)存在云服务器一块卷里。
它扛得住"重新部署",但**扛不住整台服务器坏掉**——没异地副本就是单点。

## 我做了什么、实测看到了什么
写了个备份工具 `KMFA/tools/app_state_backup.py`,并**当场从云端真跑了一遍完整往返**:
1. **备份**:把状态打包(SQLite 用"一致快照",即便正在写也不会抓到半截数据)→ 推到 **GitHub 私有库**。看到:`✓ 异地备份完成 438 字节 3 文件`。
2. **列表**:`list` 真列出这条备份。
3. **还原**:从私有库下载 → sha256 完整性校验通过 → 解包到新目录。
4. **逐一比对**:JSONL 逐字节一致;SQLite 表里的拍板记录还原后**完全一样**。
5. **没令牌时的降级**:也验了——会写本地副本并**明确告警"异地未激活"**,不会假装成功。
6. 自测用的是**假数据**,测完**已把测试对象从私有库删干净**。

## 云端怎么自动跑
- 排程早就有:每天**北京 00:30**自动跑 `daily-backup`(原来是空转,现在改成真备份)。
- 让备份能读到状态:skills 容器**只读**挂上状态卷(只读、绝不写)。

## 还差一步(你定,很简单)
异地备份要往 GitHub 私有库推,需要一把"钥匙"(`KMFA_BACKUP_GH_TOKEN`)。
- **设了**(在 Coolify 面板加这一项,跟你当初加 `COOLIFY_API_TOKEN` 一模一样)→ 每天自动异地备份到 GitHub。
- **没设**→ 自动降级:先备到服务器自己的持久卷(能扛重部署,但整机坏了会丢),启动日志会提醒你。

**所以现在:代码建好、往返实测通过、排程和挂载就位。你在 Coolify 加一把钥匙,异地备份即刻全自动。**
不想弄钥匙也行——我可以改成备份进你**钉钉云盘**(系统已登录钉钉,零额外设置),你说一声。
