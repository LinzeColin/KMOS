# S07 / P-S07-04 · T-S07-04 —— 下载与导出门禁：越权、泄露、负载、恢复

- 依赖门：`T-S07-01` / `T-S07-02` / `T-S07-03`——均在库
- 绑定验收：无（本任务是 S07 出口门禁，不绑单条 AC）
- stop_condition：**发现任何跨 workspace 文件可读，或公开缓存不可撤销**

## 授权矩阵从路由表派生，不手写

手写矩阵会和路由表脱节，而脱节的方向永远是「新端点没进矩阵」——
于是**新加的端点是唯一没被越权测试覆盖的那个**，而它恰恰是最可能忘了鉴权的那个。

这里枚举全部 15 条 workspace 作用域路由（含 `include_router` 挂进来的），
逐条 × 三种身份（本体 / 另一个 workspace / 匿名）实测。新端点自动进矩阵。

**404 而不是 403**：403 会确认「这个 workspace 存在」，等于免费送出一个存在性探测器。
伪造凭据与无凭据也必须给出**同样**的 404——两者若有差异，差异本身就是一个
可以用来判断「token 格式对不对」的预言机。

## 422 不算通过（本线第二次踩这个坑）

请求体校验不过会以 422 挡在门外，鉴权代码一行都没跑。把 422 当「拒绝了，很好」，
就是又一盏覆盖为零的绿灯。所以每条路由都配了能过校验的最小载荷，
422 一律判失败并直说该补什么。

第一版的 `BODY_FOR` 键漏了 API 前缀，于是**一条都没匹配上**、全部退回 422——
测试当场红并指出原因，这正是把「422 判失败」写进断言的价值。

## 顺手修好了 TEST-DL-004 的一个真实覆盖漏洞

建授权矩阵时发现：`app.routes` 里 `app.include_router()` 的产物是 `_IncludedRouter`，
**没有 `.path` / `.methods`**。TEST-DL-004 第一版的枚举用 `getattr(route, "path", "")`
兜底成空串，于是**整个 walking-skeleton 路由组被静默丢掉**——
「有副作用 GET=0」当时只覆盖了顶层路由。

守卫用例没抓到，因为它只查「总数 ≥30 + 两条已知路径」，而那两条恰好都在顶层。
现在改成**按路由组点名**：少一组的表现和一切正常完全一样，
除非你专门去问那一组还在不在。

递归展开后重跑，仍是 **0 条有副作用的 GET**（结论未变，但现在这个结论覆盖全部路由组）。
过程中新暴露的两个 `.sqlite3` 是惰性建表，已进白名单，
并配一条用例**打开库逐表数行**——白名单条目必须被证明，不能只是被声称。

## 「签名 URL 重放/过期」是不适用，不是漏测

本仓下载**没有签名 URL 这个东西**：制品一律 POST + 凭据取。
没有可分发的 URL，就没有被转发、被日志记录、被重放的窗口，过期策略也无处可谈。

签名 URL 的整个风险面（泄露即长期可用、撤销要等过期、CDN 会缓存）
本仓通过**不引入它**来消除。一条用例把「不存在」钉住：
响应不得出现 `Location` / `X-Signed-Url` 类头，下载不得接受 `signature` / `token` /
`expires` 类参数。哪天有人加了，它会红，逼着补齐重放与过期测试，
而不是让一条无人测过的 URL 悄悄上线。

## 公开缓存：stop_condition 的另一半

一旦某个私有响应带上 `public` 或正的 `max-age`，路上的 CDN / 代理就会存下它，
而**你撤不回来**——删了源文件、改了权限、吊销了会话都没用，
缓存里那份还在，直到它自己过期。所以这不是「最好加上」，是硬门禁：
四类私有响应逐个断言 `no-store` + `private` 在、`public` 不在、`max-age` 非正。

报错体另测一条：不得回显目标 workspace id，不得出现 `/var/lib`、`Traceback`、
`sqlite3` 之类内部细节。「找不到」这件事本身不该附带一张系统地图。

## 负载与出网

- **并发大下载**：四个 workspace 各自的制品，12 个请求并发取回，逐个校验**内容**
  而不只是状态码。并发下最典型的缺陷不是慢，是**串台**——共享缓冲区或路径变量
  让 A 拿到 B 的字节，而状态码全是 200。
- **导出洪泛**：闸是声明式的（`MAX_CONCURRENT_JOBS` / `MAX_JOBS_PER_OWNER` /
  `MAX_SYNC_ENTRIES` / `MAX_SYNC_BYTES`），且有守卫用例防止它们被改成 0 或天文数字。
- **出网费用**：单个请求能拉走的字节有上界，且上界**被执行**（用一条超限请求实证），
  不是只写在常量里。没有上界时一个请求就能把整库拉走，账单在事后才出现。

写夹具时又撞了一次同类问题：四个 workspace 共用一个 TestClient，
cookie jar 只留最后一个会话，前面几个的 Bearer 与 cookie 不一致被判越权 404。
改成每个 workspace 一个客户端——否则测出来的不是并发，是夹具自己串了台。

## 恢复

- **对象丢失** ⇒ 503 `artifact_unavailable`，不是 200 + 空文件。
  空文件是最坏的回应：调用方拿到 200 和 0 字节，会以为报告就是空的。
- **对象被改一个字节（长度不变）** ⇒ 503 `artifact_integrity_failed`。
  发出去再让用户自己发现，等于把校验推给下游，而下游多半不会校验。
