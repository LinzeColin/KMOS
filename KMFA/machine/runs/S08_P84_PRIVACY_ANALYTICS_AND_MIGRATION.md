# S08 / P-S08-04 · T-S08-04 —— 隐私统计与数据/路由迁移

- 绑定验收：`AC-PROD-004`、`AC-MIG-001`
- pass_gate：**核心事件可用≥99%、敏感命中=0；迁移差异=0 且回滚通过**
- stop_condition：第三方数据处理条款不满足隐私边界，或迁移无回退

## 统计不发第三方，这是设计不是省事

第三方统计要成立，得先满足「数据处理条款符合隐私边界」——
而本仓的用户是匿名 workspace，连账号都没有；把匿名标识发给第三方，
等于替用户做了一个他没同意、也无法撤回的决定。

所以统计留在本地。代价是没有现成看板，收益是**隐私边界不需要靠
任何一份别人的合同来保证**。

## 事件名是枚举，属性值只收桶

`event_name` 若允许自由字符串，调用方迟早会把 `f"viewed_{project_name}"`
当事件名发——项目名就此进了统计表。

属性值同理：不记「金额 12345.67」，记「金额桶 1e4–1e5」。
桶足以回答「大额操作多不多」，而原值除了泄露没有额外用处。

**这里补了一个真实缺口**：第一版的值形状正则允许数字和点，
于是 `"40960322.77"` 作为 `amount_bucket` 能原样混过去——
**原始金额就这样进了统计表，而它看起来完全合规**。
现在 `*_bucket` 属性必须含字母，纯数字一律拒绝。

匿名标识用**加盐**摘要：不加盐的话，任何拿到统计表的人都能拿一份
workspace id 列表去撞库，把匿名标识还原回去。

## 可用率的分母是「应该产生的事件数」

用「发出去的事件数」当分母，丢了的事件不在分母里，可用率永远是 100%——
**这是最常见的一种指标自欺。**

## 迁移：回滚先于切换验证

expand → dual-write → verify → switch-read → observe → contract。
关键是**回滚路径在切读之前就要验证过**：「先切过去，回滚等出事再说」的问题是，
出事时你既没时间也没心情去发现回滚脚本本身有 bug。

差异比对按**内容摘要**而不是行数：行数相同而内容错位，
是迁移里最典型也最难发现的一类缺陷。

## 实测

`tests/test_s08_product_core.py` —— 事件名枚举、五类敏感值拒收、
桶而非原值、盐必需、可用率分母、差异非零不得切读、回滚未验证不得切读、
