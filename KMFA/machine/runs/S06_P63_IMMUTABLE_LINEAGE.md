# S06 / P-S06-03 · T-S06-03 —— 不可变原件 + 安全派生物 + 完整血缘

- 依赖门：`T-S06-02`（证据 `S06_P62_QUARANTINE_PIPELINE.md`）、
  `T-S05-03`（证据 `S05_P53_CONSISTENCY_STATE.md`）——两者证据在库
- 绑定验收：`AC-UP-004`（TEST-UP-004）
- 阈值：**每个版本唯一可追溯；历史不被覆盖；血缘断点 = 0**
- pass_gate 另加：**高风险文件仅附件**

## 三条阈值各否定了一种「看起来对」的做法

| 阈值 | 它否定了什么 | 本实现怎么做 |
|---|---|---|
| 历史不被覆盖 | 按文件名去重覆盖 | 同名再传是**新版本**；版本号只增不减，删了中间版也不回填 |
| 血缘断点 = 0 | 派生物只记「我是谁生成的」 | 派生物挂在**版本**上，并记处理器**版本**与内容摘要，三者缺一不可 |
| 每个版本唯一可追溯 | 用时间戳或自增 id 当版本标识 | 标识 = `artifact_id/vN`；摘要独立记录，供比对而非充当标识 |

补充两条实现里刻意做出的选择：

- **同内容也各存一版。** 字节层面的去重是**存储**的事（content-addressed 对象层负责），
  血缘层必须如实记录发生过几次上传。两件事分开，否则会为了省空间而丢历史——
  而历史正是这一项要保的东西。
- **处理器标识必须钉死版本**，`latest` 一律拒。接受漂移标识等于放弃血缘：
  过一段时间再问「这张预览怎么来的」，答案会变成「用当时的 latest」，
  而那是什么已经查不到了。`broken_lineage()` 把这种情况也算作断点——
  断点不只是「指针断了」，「指到了但查不到那是什么」同样答不出问题。

## 「重新处理」是这一项最容易做错的地方

同一原件用新版本处理器再跑一次，产出的是**新的派生物**，**原件那一版不变**。
把重新处理写成「更新派生物」会当场制造血缘断点：
旧派生物指向的处理器版本消失，就再也答不出「当时那张图是怎么来的」。
本模块因此**只提供追加语义，不提供任何原件的修改入口**——
rollback 条款写死「派生物可删除重建，原件不可改」。

## 高风险文件仅附件

`attachment_only` 的版本挂不上任何派生物：生成预览就意味着要解析它，
而 stop_condition 明写「处理器需要执行用户文件中的代码或宏」即停止。
**不解析就不可能触发这一条**——结构性保证，不是纪律要求。

## 实测

```
TEST-UP-004  30 passed（任务包点名的五种输入各有一组用例）
后端全量    395 passed
```

覆盖：同名（历史不缩短，10 版仍是 10 版）、同内容（各存一版）、
修改版（删中间版不回填号）、派生预览（挂版本不挂文件、挂图外版本被拒）、
重新处理（旧派生物完好、原件字段逐一不变）；
处理器标识 3 组合法 / 7 组非法；血缘断点两类（悬空指针、不可追溯处理器）均被报出。

## 过程中被自己抓到的一处

单测里图省事写了 `processor="p@1.0.0"`，被处理器名长度规则拒掉，5 条用例连带失败。
