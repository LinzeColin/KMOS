- 任务包基线：`KMFA_Product_Design_Taskpack_v1.5.2`（封存件 sha256 见 `S06_P61_RESUMABLE_UPLOAD.md`）
- 依赖门：`T-S06-01`（证据 `S06_P61_RESUMABLE_UPLOAD.md`，pass_gate 已达成）
- 绑定验收：`AC-UP-003`（TEST-UP-003）
- 阈值：**恶意/畸形逃逸 = 0；解析不在主进程执行；标准合法夹具误拒 < 1%**

## 「quarantine-first」是整个设计，不只是个名字

**默认隔离，只有明确判干净的才放行。** 反过来做（默认放行、发现坏的再拦）
在这里行不通：阈值要求逃逸为 0，而「发现坏的」永远滞后于「出现新的坏的」。

## 接在哪：持久化的**唯一入口**，不是各个上传入口

扫描放进 `_persist_completed_upload()`。放在入口的话，每加一条上传路径
就要记得加一次扫描，漏一次就是一条不设防的通道；放在持久化唯一入口，
则「能落库的都扫过」是**结构性**成立的，不靠谁记得。

判不干净就不进持久化链——不是先存起来再打标记。存下来的那一刻它已经在系统里了。

## 四类逃逸，各有落点

| 类别 | 判据 | 为什么必须这么判 |
|---|---|---|
| 路径穿越 / NUL 截断 / 保留设备名 / 结尾点空格 | `safe_filename()` | 这些在**存储**层出事（写到隔离区之外），所以必须在落盘前判，而不是预览前 |
| MIME 欺骗 | `magic_conflicts()` | 只信客户端声明等于没验，只看扩展名同理。以**内容**为准 |
| EICAR | 内容签名 | 行业约定的自检样本，命不中说明这条链根本没在扫 |
| zip bomb / zip slip / 嵌套 | `inspect_archive()`，**只读中央目录绝不解压** | 炸弹的杀伤力全在解压；先解压再看大小，那时机器已经在挨打了 |

问题非空即隔离，**不做「清洗后放行」**：悄悄改名会让用户拿到一个他没上传过的
文件名，而攻击者拿到的是一次免费重试。

## 「解析不在主进程」怎么保证

本模块**不做任何解析**，只做判定，输出 `may_parse` 让上层决定是否交给隔离解析器。
判定本身零解析，所以恶意文件不可能在判定阶段触发解析器漏洞——
这是结构性保证，不是纪律要求。

`scan_timeout` 与 `quarantined` **分开**：前者是「我们没判完」，后者是「我们判定它坏」。
混在一起会让「扫描器挂了」看起来像「文件是恶意的」，运维会去查错的方向。

## 误拒 < 1%：反向阈值，防的是把前两条做过头

把所有东西都判恶意，逃逸确实为 0，产品也确实不能用了。所以：

- 每加一条规则都要能回答「哪个正常文件会被它误伤」，答不上来的规则不加；
- `detected=None`（判不出）**不算欺骗**——否则所有新格式都会被误拒；
- zip magic 与 docx/xlsx/epub 声明**兼容**——它们本来就是 zip 壳，
  不认这条会造成大批误拒。

实测夹具（png/jpg/pdf/txt/csv/json/未知二进制/xlsx 结构）**零误拒**；
既有 300+ 条上传相关测试接入扫描后**一条未红**，这本身是集成层的误拒率证据。
