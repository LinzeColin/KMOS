# S10 / P-S10-01 · T-S10-01 —— 三平面、匿名所有权与文件攻击面建模

- 绑定验收：`AC-ARCH-001`
- pass_gate：所有高风险威胁有**预防、检测、响应和验收 Oracle**
- stop_condition：现有架构无法隔离未公开数据，继续开放会泄露

## 每条高风险威胁必须四件齐全

只写「风险：数据泄露」没有任何用——它不能被验证，也不能被反驳。
所以每条高风险威胁都要带：**预防**（怎么让它发生不了）、
**检测**（发生了怎么知道）、**响应**（知道了怎么办）、
**Oracle**（拿什么证明前三条是真的）。

第四条是关键。**没有 Oracle 的威胁条目是一段声明**，
而声明在事故复盘里唯一的作用是证明我们当初想到过。

## 覆盖率报成缺口清单，不报百分比

百分比会让「92% 覆盖」听起来不错——而缺的那 8% 才是重点。
`threat_coverage` 返回 `gaps` 逐条列名，`complete` 是布尔而不是比率。

## 本仓已落地的高风险威胁与其 Oracle

| 威胁 | Oracle |
|---|---|
| 跨 workspace 读取 | 15 路由 × 3 身份矩阵（S07/T-S07-04，30 条实测全 404） |
| 未公开数据被公开缓存 | 四类私有响应逐条断言 `no-store`+`private`，`public` 不在 |
| 恶意文件触发解析器 | quarantine-first（S06/T-S06-02），且明确不引入图像/PDF 解码器 |
| 归档端 zip-slip | 条目名强制剥路径成分（S07/T-S07-02） |
| 读请求产生业务副作用 | 全路由组枚举 + 前后状态 diff（S07/T-S07-03，有副作用 GET=0） |
| 匿名标识被还原 | 加盐摘要，且盐缺失即抛（S08/T-S08-04） |
