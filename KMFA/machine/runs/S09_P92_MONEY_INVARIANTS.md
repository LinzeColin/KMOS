# S09 / P-S09-02 · T-S09-02 —— 金额、舍入与零差额不变量

- 绑定验收：`AC-FIN-001`
- pass_gate：所有精确测试通过，**权威浮点字段=0**
- stop_condition：口径无法确定且错误会影响财务决策

## 金额是整数分，且**拒绝 float 而不是转换 float**

`0.1 + 0.2 != 0.3` 在报表上的表现不是「差一点点」，是**对不平**——
而对不平会被当成业务问题去查，查上半天才发现是二进制浮点。

不用 `Decimal` 而用 `int`：`Decimal` 仍然可以被误乘一个 float 而降级，`int` 不会。

**拒绝而不是转换**：转换会让 `2.675` 变成 `267`（不是 268），
而调用方不会知道自己刚刚丢了一分钱。拒绝则当场暴露。

## 分摊保证合计等于总额

用最大余数法（按比例取整，余数补给余数最大的几项），而不是各自 round 再相加——
后者几乎必然差几分，而**「合计对不上明细」是财务报表里最招人质疑的一种错误**。
同分时按索引补，保证确定性：不确定的分摊会让两次报表出现不同的明细。

## 零差额不设容差

设容差（「差 1 分算平」）等于把对账变成一句安慰：
真正的错误常常就是一分钱起步，而容差恰好把它盖住。

## 比率用万分比整数

毛利率写成 `2537`（25.37%）而不是 `0.2537`。浮点比率在累加与比较时
会带来和金额一样的问题，而它同样会进报表。收入为 0 时毛利率给 `None` 而不是 0——
**给 0 会在图表上画出一条「毛利率 0%」的线，那是编造。**
计算先乘后除：先除会在整数除法里直接归零。
